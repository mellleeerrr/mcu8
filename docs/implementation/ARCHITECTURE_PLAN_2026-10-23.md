с «нового примитива» на **компактный синтаксис поверх существующего примитива** —
это ровно тот случай, где «меньше кода» и «больше кода» совпали бы по стоимости.
Я выбрал формат **областей на модульной сетке** (`Region{x0,y0,x1,y1,cols,rows}`),
потому что он читается один-в-один со словами спецификации («2/3 ширины, 1/3 высоты»),
а разворачивается в **ту же самую** арифметику `cell_rect`, что и вендорные пресеты:
новой геометрии в проекте не появилось, появился только новый *синтаксис данных*.

## 3. Раскладки Codian: как получена геометрия

### 3.1 Модель данных

```
CodianScheme { title, den, regions: &[Region], pips: &[Pip], roles: &[SlotRole] }
Region      { x0, y0, x1, y1, cols, rows }   // область на сетке 1/den, делится на cols×rows окон
Pip         { x0, y0, x1, y1 }               // наложенное окно, z_order = 1
```

* `den` — знаменатель модульной сетки (у `#41` — 60, у `#43` — 28, у `#49` — 36,
  у PIP-раскладок — 1000);
* окно = `cell_rect((x, y, w, h), den, den, canvas)` — **та же** формула
  `floor(coord * canvas / grid)`, что и у вендорных 65 пресетов ⇒ один путь арифметики,
  бесшовная сетка, ноль щелей;
* `roles` — только у двух кастомных раскладок.

### 3.2 Откуда взяты пропорции

| Источник | Что даёт | Уровень доверия |
|---|---|---|
| Текст спецификации, поле «Геометрия: …» каждого макета | число окон, состав, явные дроби (2/3, 1/3, 4/9, 5/6, 9/16) | **истина** для топологии и пропорций |
| 52 чертежа вендора из того же `.docx` | независимая проверка топологии | **истина** для топологии, **схема** для пропорций |
| Вендорный UI TrueConf PNM 2.2.1.66 | 25 видеоокон, ручной режим, выбор схемы | контракт UI |

**Доказательство, что чертёж схематичен:** для макета #5 спецификация говорит
«1 крупное окно (2×2 ячейки, **4/9 экрана**)», а чертёж показывает крупное окно
высотой 2/5. Значит, ни текст, ни картинка не дают точных пикселей — дают структуру.
Отсюда решение: **структура — по спецификации, пропорции — рациональные (ближе всего
к обоим источникам), а измерения чертежей — оракулом теста с допуском ±2 px.**

### 3.3 Проверка

`crates/vks-layout/tests/codian_layouts.rs` (6 тестов) + независимый скрипт сверки:

* число окон каждого из 52 макетов совпадает со спецификацией — **52/52**;
* карта «крупных» окон (площадь > 1,5 × медианной) совпадает с чертежом — **52/52**;
* основные окна **ровно** покрывают канвас: сумма площадей = площадь канваса,
  попарных пересечений нет;
* наложенные PIP идут последними, `z_order = 1`, лежат внутри канваса;
* области делятся на целые ячейки; роли совпадают по числу с окон.

> Сверка выполнялась тремя независимыми способами: (1) мой Mondrian-парсер
> чертежей, (2) собственная реализация агента `elegance-reviewer`,
> (3) сверка «спека ↔ чертёж» по числу окон и карте крупных окон.
> Первые два раунда выявили **три мои ошибки**: перевёрнутые ярусы (`#21`, `#23`,
> `#29`, `#31`, `#42` — инвертировать надо геометрию, а не порядок списка),
> неверные индексы квадрантов (`#34` = ПН, а не ПВ) и перепутанный счёт окон
> в PIP-раскладках. Все три исправлены, после чего совпадение стало 52/52.

### 3.4 Две кастомные комбинированные раскладки

| | `codian_custom_22` | `codian_custom_14` |
|---|---|---|
| Сетка | 12×5 (крупные блоки — по 2,5 колонки) | 6×4 |
| Крупный блок 1 | `Fixed` (закреплён) | `Fixed` |
| Крупный блок 2 | `Active` (активный докладчик) | `Active` |
| Малые окна | 18 в нижнем ярусе 6×3 | 12 в двух рядах 6×1 |
| Роли | Rolling 16, default 4 | Rolling 6, default 6 |
| Итого | **22 окна** | **14 окон** |

Роли назначает чистая функция `assign_by_role(roles, fixed, active, participants)`:
`fixed` → приоритет №1, `active` → №2, `rolling` → участники по кругу из
оставшихся, `default` → остальные в порядке прихода. Покрыта 5 тестами.

### 3.5 Интеграция

* `POST /api/v3/ui/video_layouts/calculate` принимает 65 вендорных + 54 Codian
  (`is_known_preset`), сообщение об ошибке перечисляет диапазон `codian_*`;
* `GET /api/v3/ui/video_layouts/presets` — **новый** аддитивный маршрут: справочник
  всех 119 пресетов с названиями и числом окон (вендорный контракт
  `/api/v3/ui/video_layouts` не изменён);
* `gateways.rs::apply_layout` — ветка Codian **до** разбора `PresetId`
  (id Codian не разбираются вендорной грамматикой);
* `resources.rs::preset_size` — теперь требует префикс `preset_` (иначе `codian_01`
  читался как размер 1).

**Приёмочный гейт не сломан:** 65 manual-пресетов, 6 custom-схем, 1-based
`calculate`, фикстура 879 слотов / 0 расхождений, `MANIFEST.sha256` 212/212,
sha256 инлайновых скриптов CSP без изменений.

### 3.6 Грамматика id пресетов палитры PNM (S16)

Палитра раскладок вендорного PNM (65 ручных схем + 26 базовых имён +
`preset_default_13` = **92 id**) и справочник Codian (54 раскладки) — разные
вещи: Codian — это раскладки комнаты, PNM-пресеты — палитра «как расставить
участников». Раньше грамматика `PresetId::parse` покрывала не весь словарь
вендора, и это было **пользовательским дефектом, а не косметикой**:

| id вендора | что происходило | стало |
|---|---|---|
| `preset_square_24` | канонизировался в `preset_equal_24` — такого id у вендора нет ⇒ таблица не найдена ⇒ **равная сетка 5×5** вместо палитры «квадрат» | `PresetScheme::Square` — отдельная схема (у вендора 4 крупных окна в центре сетки 6×6 + 20 мелких) |
| `preset_double_triple_11` | не разбирался (`triple` не было в словаре позиций) ⇒ пресет не доезжал ⇒ равная сетка | `Position::Triple` |
| `preset_selected_rbl_13` | не разбирался (`rbl` не было в словаре позиций) ⇒ равная сетка | `Position::Rbl` + топология из иконки вендора (крупное вверху по центру, мелкие по бокам и снизу) |

Правило, которое теперь действует: **canonical id обязан быть ключом в
`MANUAL_SCHEMES`**. Проверяется тестом `canonical_geometry_matches_manual_reference`
(все 65 ручных пресетов) и гейтом на сервере
(`vendor_manual_presets_keep_reference_geometry`).

Чего мы **не** сделали и почему: динамическая (не-ручная) геометрия расходится с
вендорской на 45 пресетах из 54 сопоставимых, и у вендора нет эталона для
произвольных размеров ⇒ любая правка была бы угадыванием. Заведено как S16b
в трекере: нужен живой эталон (как `reference_calculate_1280x720.json`).

## 4. Пошаговый план архитектуры

Легенда: **[С]** сделано в этой сессии, **[П]** запланировано, **[A]** — работа
вне текущего контура (требует стенда/железа).

### Шаг 0. Фундамент данных раскладок — **[С]**

Единый источник геометрии в `vks-layout`: вендорные 65 пресетов + 54 раскладки
Codian, одна формула пиксельной арифметики (`cell_rect`), один справочник ролей.
*Результат:* UI-каталог раскладок расширен без изменения контракта эталона.

### Шаг 1. Медиа-контур MCU: владение кадрами — **[С]**

`Arc<Frame>` вместо `Frame` в карте кадров + `rekey_frames` (перенос кадра за
участником при смене раскладки) + регресс-тест.
*Результат:* −1 ГБ/с memcpy на комнату, устранён устаревший кадр в окне.

### Шаг 2. Устойчивость процесса — **[С]**

`panic = "unwind"`; `libc::kill(-pgid, SIGKILL)` вместо порождения `/usr/bin/kill`;
`scrubbed_env()` + stderr ребёнка в диагностику; `read_to_end`/`read_encoded_*`
 poisoning-корректны; `validate_audio` / `validate_for` / `validate_decode`;
лимит H.265 4096×2160 с исправленным комментарием.

### Шаг 3. Доведение раскладки до браузера — **[П]** (критично, цепочка Ц7)

`LayoutChanged` объявлен в `signaling.proto`, но **никогда не отправляется**, а
клиент `MediaEngine::render` всегда рисует авто-сетку ⇒ раскладка, выбранная в UI,
до браузера не доходит. Требуется: отправка события при смене раскладки,
`pinned`/`is_focus` в `LayoutDescriptor` (сейчас `#[non_exhaustive]`-нет — добавление
полей ломает литералы), приём на клиенте и отрисовка по слотам.

### Шаг 4. Сквозная идентичность раскладки — **[П]** (критично, цепочка Ц8)

`gateways.rs` строит `geometry[]` из массива, но `position` из UI — 1-based со
сдвигом `base`; в `sanitize_assignments` это приводит к молчаливому отбрасыванию
участников. Нужен единый 0-based `slot_id` на всём пути
`UI → LayoutDescriptor → engine → client`, без «минус база».

### Шаг 5. WebRTC как полноценный транспорт — **[П]** (цепочки Ц1–Ц6)

* реальный WebRTC-пир **не регистрируется** как паблишер (`lib.rs:879-890`);
* WebRTC-комнаты не связаны с MCU/SIP/H.323 (`lib.rs:752-768` — явные «unsupported»);
* `VKS_TRANSCODER_ENABLED=1` открывает в SDP кодеки, которых нет в рантайме ⇒
  звонок умирает после 200 OK; нужен `codec_capabilities`-гейт на SDP;
* `MAX_PEERS_PER_ROOM = 2`; `VKS_WEBRTC_TRANSPORT` выключен по умолчанию;
* ICE-lite без TURN, `ice_servers` не используются в str0m-пути.

### Шаг 6. Роли и поведение раскладок Codian §2 — **[П]**

Семейства раскладок, voice activation, «Important», self-view, приоритет заполнения,
FECC/DTMF, глобальные команды. Из 8 пунктов реализовано ≈ 0.
**Ограничение архитектуры:** `McuEngine` композитит **один** кадр на всех
зрителей ⇒ per-viewer self-view (свой вид в своём окне) невозможен без
перехода на per-viewer композицию. Это отдельное архитектурное решение, а не задача
на день.

### Шаг 7. Роли в движке: ротация и активный докладчик — **[П]**

`assign_by_role` готов и покрыт тестами; не хватает: `join_order` в движке
(сейчас `publisher_tracks: BTreeMap<ParticipantId, _>` — сортировка по UUID, а не по
порядку прихода), триггера переназначения и передачи `active_speaker` наружу
(`is_speaking` сейчас жёстко `false`, `SpeakingStateChanged` парсится, но эмиттера нет).

### Шаг 8. Мёртвый код и мусор — **[С]**

Сделано (раунд 1): `renderer.rs`, блок `catalog()`, `expected_slot_count`, копия
`MANUAL_PRESETS`, `CompositeFrame`, 3 мёртвых символа, `artifacts/` 949→247 МБ,
12 отчётов прогонов перенесены в `docs/progress/evidence/`, корень репозитория
вычищен, `.work-tmp/` в `.gitignore`.
Сделано (раунд 2): 32 мёртвые `pub fn`/константы в 10 крейтах, 3 копии
(`csv_escape` → `vks-admin/src/util.rs`, `truthy` → `vks-common::codec_capabilities`,
`canonical_default_payload` → `vks-common::layout_defaults`), 3 неиспользуемые
зависимости, `PixelRect::to_rect`, устаревшие док-строки `vks-layout`, `.gitignore`,
`configs/default.toml` (хардкод `candidate_addr` → `203.0.113.10`).
Осталось: `focus.rs` — канонизация (живая реализация инлайн в `engine.rs` ⇒ B8),
`oxideav` — no-op фича, `csv_escape` в `audit.rs` — **оставлен как есть**: у него
другая семантика (разделитель-запятая по RFC 4180 и без защиты от CSV-инъекции),
слить его с парой `export`/`observability` без решения владельца — значит сломать
выгрузку аудита.

### Шаг 9. Фронтенд-импорт PNM — **[П]**

P1-1 (потеря `<script>`-тегов), P1-2 (скрипт никогда не падает), P1-5 (наполовину
импортированное дерево), общий `scripts/pnm_patch_lib.py` (≈80 строк) вместо
дублирования в двух скриптах. CSP при этом не затрагивается: инлайновых `<script>`
не появляется, меняется только существующий чанк и `MANIFEST.sha256`.

### Шаг 10. Инфраструктура и CI — **[С]**

`vendored-protoc` нерабочая в путях с пробелом: `protobuf-src` 1.x собирается через
autotools/libtool, а `$PWD` режется пробелом в «Рабочий стол» ⇒ фича удалена,
вместо неё `protoc-bin-vendored = "3.3"` (ADR-0031), `build.rs` 52 → 44 строки;
**сгенерированный код побайтово идентичен** (4 файла + дескрипторы 25049 Б) ⇒
смена protoc ничего не меняет в протоколе. CI переписан: `--locked` и
`--all-features` во всех шагах, `--no-fail-fast`, кэш cargo, `ubuntu-24.04`,
новые джобы `check` / `path-with-spaces` / `doc` (`RUSTDOCFLAGS="-D warnings"`) /
`test-serial` (`--test-threads=1`), `cargo deny --all-features` (все 9 новых
крейтов — MIT, advisory нет).
Осталось: 5 «зарегистрированных, но никогда не записываемых» метрик;
`AppState.recorder`/`AppState.cluster` — поля только на запись (запись
конференций и кластерный lease-фенсинг в проде не работают) ⇒ B7, решение
владельца: `Feature` или удаление.

### Шаг 11. Железо и живые терминалы — **[A]**

Live-H.323 и SIP-приёмка, WebRTC в реальном браузере, нагрузка 30 fps × N комнат,
TURN. Без стенда эти пункты не закрываются кодом.

## 6. Открытые вопросы: состояние на 2026-10-23

Все пять вопросов, вынесенных владельцу, **решены** (мандат «делай»).
Ниже — итог и то, что осталось открытым уже после решений.

| Вопрос | Решение | Как сделано |
|---|---|---|
| Namespace id Codian | `codian_01…codian_52` + `codian_custom_22` + `codian_custom_14` | `crates/vks-layout/src/codian.rs`; справочник отдаёт `source: "codian"` |
| `panic = "abort"` | `unwind` | `Cargo.toml` workspace; `catch_unwind` в воркерех доступен |
| `artifacts/` | отдельное хранилище | `$XDG_STATE_HOME/vks/artifacts` (fallback `~/.local/state/vks/artifacts`), 247 МБ вынесены из репозитория |
| per-viewer self-view | делать, отдельной инициативой (ADR-0029) | фазы 0–2 сделаны: `Arc<Frame>` вместо копий, чистый планировщик `plan_viewer`, персональная дельта из двух прямоугольников |
| H.263 320×240 | «не реализовано» → `VideoCodec::H263Plus` → `h263p` | кодируется 320×240 и 640×480 через AVI-контейнер; остаток — нет RTP-payloader (RFC 2429) ⇒ сквозной SIP-мост H.263 не работает |
| Грамматика id пресетов | расширять под словарь вендора | `Position::Rbl`/`Triple`, `PresetScheme::Square`; round-trip без потерь для всех 65 ручных пресетов |

| Живой стенд 8080 | пересборка release + рестарт `vks-mcu.service` | **сделано 19:36**: release пересобран, юнит перезапущен через `busctl --user … RestartUnit`; live `/presets` отдаёт `slots` у всех 54 Codian, `calculate` → 200, `/pnm/` отдаёт проектный слой. Детали — `docs/implementation/LAYOUTS_UI_CHAIN_PLAN_2026-10-23.md` §7.6 |

**Открыты после решений (нужен либо владелец, либо живой эталон):**

1. **S16b — динамическая геометрия не совпадает с вендорской.** На 54
   сопоставимых пресетах generic-путь отличается в 45. Нужен живой эталон
   вендора (как `reference_calculate_1280x720.json`): без него любая правка —
   угадывание. Ручные размеры (65 пресетов) закрыты таблицей ⇒ пользовательский
   дефект не виден, но номера не-ручных пресетов рисуются «как получится».
2. **`assign_by_role` не вызывается автоматически** (последний пункт S12): в
   `LayoutDescriptor` нет ролей окон, а `layout_id` из UI не гарантирует
   `codian::roles(id)`. Разбор вариантов и подводных камней —
   `docs/progress/evidence/s12-voice-seating/README.md`.
3. **B7 — cluster lease fencing и recorder write-only в проде:** `Feature`
   (включать по флагу) или удаление.
4. **Покрытие SIP/H.323** — интеграционный тест входящего звонка бьёт по
   тестовым дублям (`incoming_sip_call`/`incoming_h323_call`), а не по боевому
   пути в UAS-цикле: это дыра в покрытии, а не мёртвый код.
5. **H.263 без RTP-payloader** (RFC 2429): кодек кодирует 320×240/640×480 в
   AVI, но сквозного SIP-моста нет — нет ни payloader'а, ни потребителя, а
   писать изолированный код без потребителя противоречит правилу «без мёртвого
   кода». Нужен вместе с медиа-плоскостью SIP-моста.

**Закрыто после этого документа:** B8 — `FocusLayout::compute` удалён,
фокусная геометрия канонизирована в `vks_layout::focus::slot_rects`, а правила
пересадки — в `refresh_seating` (`promote_to_main_window` убран как полумера);
`docs/architecture/LAYOUT_ENGINE.md` приведён к коду (v0.2, ложные утверждения
исправлены); слой проекта PNM остаётся в репозитории
(`client/pnm-frontend/project-layer/`), импорт сохраняет его блоком с маркерами.
