## 1. Цель и критерии готовности

**Цель.** На странице раскладок нашего MCU
(`http://127.0.0.1:8080/pnm/monitoring/conferences/<id>/layouts`) видны **все
наши раскладки** — 65 вендорных manual-схем (уже рисует сам UI) и **54
раскладки Codian MCU 4200** (`codian_01`…`codian_52`, `codian_custom_22`,
`codian_custom_14`) — в **том же стиле и дизайне 1:1**, без дублирования схем, с
рабочей цепочкой до композита MCU.

**DoD (проверяемое):**

| # | Критерий | Как проверяем |
|---|---|---|
| 1 | На странице раскладок 54 карточки Codian в оформлении вендорских (те же классы, размеры, подписи-локали) | скриншот + DOM: `document.querySelectorAll('[data-source=codian]').length === 54` |
| 2 | Дубликатов нет: вендорские 65 manual-схем не появляются второй раз; наши id (`codian_*`) уникальны | сверка id-множеств: vendor 65 ∩ codian 54 = ∅, в DOM нет повторов id |
| 3 | Превью любой Codian-схемы строится корректно (число окон и карта крупных окон по §2 спецификации) | `POST /api/v3/ui/video_layouts/calculate {preset:"codian_XX"}` → slots; сверка с `vks_layout::codian::geometry` |
| 4 | Применение схемы доходит до MCU: слоты и геометрия в композите, клиенту уходит `LayoutChanged` | live: применить схему → `current_layout` в движке, `LayoutChanged` в сигналинге, слоты = таблице |
| 5 | Вендорские схемы, авто/динамический режимы и существующий дизайн не изменились | регресс: страница как была, вендорский пайплайн `payload.preset` не тронут |
| 6 | Гейт зелёный | `cargo fmt --check`, `clippy -D warnings`, `test --workspace` — exit 0 |
| 7 | Гигиена: конфиги прочитаны целиком (`cat`), дубли/мёртвые ключи и файлы либо удалены, либо обоснованы | evidence-отчёт со списком |

**Ограничения.** Дизайн/стиль не меняем — только добавляем; вендорское дерево
`client/pnm-frontend/deployed/pnm` руками не правим (только через
`scripts/import-pnm-frontend.sh` + проектный слой); сторонние ассеты не
устанавливаем (никакого React/Vue — только наш проектный слой); русские
комментарии и документация, идентификаторы английские, без эмодзи.

## 3. Архитектура решения

```
[1] каталог      GET  /api/v3/ui/video_layouts/presets      (есть; 65+54, source)
                 ↓ проектный слой берёт только source=="codian"
[2] превью       POST /api/v3/ui/video_layouts/calculate    (правка: + codian_*)
                 ↓ slots[{position,x,y,width,height,z_order}] — тот же контракт
[3] рендер       проектный слой вставляет группу «Codian MCU 4200» в страницу
                 раскладок теми же классами/локалями, что у вендорских схем
[4] применение   существующий flow UI → POST layout-документа с payload.preset
                 = "codian_XX" → gateways.apply_layout → codian::geometry → MCU
[5] доставка     LayoutChanged + композит (есть)
```

Изменения по слоям:

**A. Backend (минимально, одна точка).**
`video_layouts_calculate`: если `is_known_preset(name)` — как сейчас; иначе
`vks_layout::codian::geometry(name, w, h)` → тот же JSON (position 1-based,
z_order). Ничего больше в вендорском контракте не меняется. Плюс тест: 54/54 id
дают геометрию, число слотов = `slot_count`, id вне словарей → 400 (как сейчас).
Оценка: ~15 строк + 2 теста.

**B. Frontend (проектный слой, не бандл).** Новый файл
`client/pnm-frontend/project-layer/codian-layouts.js` (+ регистрация в
`scripts/import-pnm-frontend.sh` в списке проектного слоя, чтобы переживало
импорт):

1. ждёт появления страницы раскладок (по `data-qa`/route), не по таймеру —
   `MutationObserver` + идемпотентная вставка (повторный вызов не дублирует);
2. берёт токен из того же хранилища, что UI (localStorage/`Authorization`), и
   запрашивает `/api/v3/ui/video_layouts/presets`; при 401 — тихий выход без
   ломки страницы;
3. для каждой codian-схемы — карточка **теми же** классами/разметкой, что
   вендорская (копия структуры из вендорского DOM, локаль через `$pgettext`-строки
   не дублируем: подпись = `title` из справочника + «Codian MCU 4200»);
4. превью — `calculate` (батч по требованию, кэш в памяти);
5. клик → тот же путь применения, что у вендорской карточки (найти обработчик по
   DOM/сети и вызвать тот же endpoint с `payload.preset = codian_XX`), без
   собственного состояния раскладки;
6. никаких инлайн-скриптов сверх проектного слоя (CSP), только внешний файл.

**C. Проверка цепочки (E2E).** Последовательность: список → превью → применение →
`current_layout` движка → `LayoutChanged` → композит (пиксели/слоты). Отдельно
live-прогон на 8080 (аутентификация из UI-сессии) и сверка 54/54 с
`codian::geometry`.

**D. Гигиена всей цепочки.** `cat` всех конфигов (workspace `Cargo.toml`, 16
крейтов, `configs/*.toml`, `deploy/vks.env.example`, systemd-юниты, CI,
`.gitignore`, скрипты импорта) → список дублей/мёртвых ключей/конфликтов →
удаление или обоснование. Плюс проверка «конфликтующих файлов»: исторические
планы, старые контракты, копии справочников раскладок.

## 6. Риски и подводные камни

1. **Минифицированный DOM.** Селекторы по классам вендора хрупкие: версия UI
   зафиксирована (2.2.1.66), но при обновлении вендора слой должен деградировать
   тихо (нет якоря → ничего не делаем, страница работает как раньше).
2. **React перерисовывает страницу** — вставленный блок может быть затёрт;
   нужен `MutationObserver` + проверка «мой блок на месте» без зацикливания.
3. **Токен.** Если проектный слой не сможет получить токен (другое хранилище),
   fallback: собственный запрос через тот же axios-инстанс UI недоступен ⇒
   используем `fetch` с заголовком из `localStorage` (проверить оба ключа).
4. **Дубли.** Вендорская сетка уже содержит 65 manual-схем; добавляем только
   codian. Наш справочник 65 в UI не подмешиваем.
5. **Превью.** `calculate` должен отдавать `position` 1-based и `z_order` как у
   вендора (для PiP/overlap), иначе превью Codian «схлопнется» в равную сетку.
6. **Применение.** `payload.position_base = 1` (по умолчанию) — наши таблицы
   отдают 1-based позиции; `payload.preset` должен дойти без нормализации id.
7. **Импорт PNM** перезаписывает дерево рантайма ⇒ `codian-layouts.js` обязан
   быть в проектном слое (иначе исчезнет после `import-pnm-frontend.sh`).
8. **CSP.** Только внешний файл проектного слоя, без инлайна.
9. **Не менять per-viewer/self-view и голосовую активацию** — они уже в проде
   этого раунда.

### 7.3 Фронтенд: проектный слой

`client/pnm-frontend/deployed/pnm/codian-layouts.js` (~400 строк, без нового CSS
и инлайн-скриптов):

- токен — `localStorage["TrueConfMCU_AccessToken"]` (тот же, что у UI);
- один `GET /api/v3/ui/video_layouts/presets` → 54 карточки;
- иконка — SVG по `slots` каталога, `viewBox` = bbox слотов (каталог в px
  канваса 1280×720, иконка масштабируется целиком); ячейки разделены зазором
  `half = max(1, round(maxX*0.01))`: 2·half = 26 канвас-px ≈ 0.9 px в иконке
  44×28 px (фиксированные 3 px давали 0.2 px — иконки слипались), отступ только
  по внутренним сторонам макета, внешняя граница flush, `rx = half`;
- группа «Codian MCU 4200» вставляется секцией на полную ширину под
  `.base-layout-configurator` теми же классами, что вендорская палитра
  (`.main-form-section-16`, `.layout-scheme-selector*`), идемпотентно, с
  `MutationObserver` + `$subscribe`. В левую панель 300 px группа **не**
  ставится: живой замер (Playwright, 1600×1200) показал, что 54 карточки
  поднимают панель до ~694 px, а `.layout-grid-content` держит 16:9 по высоте —
  предпросмотр растягивается до ~1513 px и вылезает за карточку; в ряду по 8
  карточки сжимаются до ~26 px. Секция на полную ширину даёт карточки 52×36 —
  ровно как у вендора;
- выбор схемы — штатный путь вендора: `layout-editor.editValueField("preset", id)`
  + `setSlots(id, …windows…)`; сохранение/применение — вендорские кнопки;
- деградация тихая: нет редактора/токена/каталога — группа не появляется.
