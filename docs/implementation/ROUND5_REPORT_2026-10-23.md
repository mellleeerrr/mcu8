# R5 — итоговый отчёт: «Конструктор» как режим, полная цепочка meeting-grid-layout, гигиена

Дата: 2026-10-23. База: R4 (`328c943`, `1fdeb9c`) + незакоммиченные правки R5.
Связанные: `ROUND5_PLAN_2026-10-23.md`, `ROUND4_REPORT_2026-10-23.md`,
`ARCHITECTURE_PLAN_2026-10-23.md`.

## 1. Что сделано

### 1.1 Пункт «Конструктор» в селекторе режимов (пункт 1 мандата)

В `.layout-mode-selector` после «Ручная настройка» добавлен четвёртый пункт
ровно в вендорской разметке: `div.layout-mode-selector-item`,
`data-qa="layout-mode-selector-constructor"`, `p.layout-mode-selector-item__text`
«Конструктор», `p.layout-mode-selector-item__description`, класс
`layout-mode-selector-item--active`. Пункт вставляется до host-gate, поэтому
виден и в auto/dynamic; клик ставит `editor.mode = 'manual'` (свойство
редактора, не поле формы — `editValueField('mode')` портил payload), активирует
пункт и раскрывает секцию конструктора; активность синхронизируется с
`preset.startsWith('vks_')`.

Live: в auto пункт присутствует (`tileInSelector=true`), секция скрыта
(`ctorHidden=true`), после клика — `active=true`, секция раскрыта.

### 1.2 Полная цепочка meeting-grid-layout (пункт 2)

Сверено с исходником библиотеки v1.9.0 (commit `1965de05`, 1733 строки) и
бандлом PNM 2.2.1.66. Вендорский круг «сохранить → прочитать» сохраняет только
`payload.{mode,preset,type}`; `calculate` принимает только `{preset,width,height}`
— поэтому единственный носитель геометрии — **id**, и он обязан заканчиваться
числом окон (вендорский `Iee`).

Реализовано в `crates/vks-layout/src/grids.rs`:
- грамматика `vks_grid[_gG][_mM]_N`, `vks_pin_<l|r|t|b>[_gG][_mM]_N`;
  канонический порядок `g`→`m`, каждый один раз, значения 1..=64; срезается
  вендорский вариант `_(2)`; `slot_count`, `MAX_WINDOWS`;
- галерея — **равные ячейки**, последний неполный ряд центрирован
  (модель библиотеки; раньше ряд растягивался и ячейки были разного размера);
- pin — порт поиска ленты: миниатюры **16:9**, зона ленты 10–40% (вертикальная)
  и 12–45% (горизонтальная), крупный участник — остаток за вычетом зазора;
- зазоры/поля (`GridOptions.gap/margin`) масштабируются по высоте холста
  (эталон 720p): `g8/m16` на 1080p = 12/24 px;
- целочисленный разрез по краям — без щелей и наложений на 1 px;
- порог «миниатюра ≥40 px» масштабируется (`40·inner_h/720`) — иначе превью
  и композит выбирали разные сетки (найдено агентом r5-chain-gateways).

Не переносится в пиксельный композит осознанно: `pinOnly` (страницы состояния
комнаты, не свойство раскладки), пагинация/«+N more» (нет рендера текста,
страница — состояние комнаты; R6), spring-анимации (crossfade 300 мс уже есть
в `layout_bridge.rs`), per-item aspect ratios (композитор делает letterbox).

### 1.3 Бэкенд-цепочка

- `calculate` принимает опции из id; `mode` не подменяет `vks_*`;
- `apply_layout`: для Codian/конструктора координаты из id **побеждают**
  присланные клиентом x/y (закрыт units-риск 1280/1920); warn при переполнении
  (участников больше окон) — лишние больше не исчезают молча;
- `recalc_layout_size` выводит `payload.size` из id конструктора **раньше**
  устаревших `slots` (иначе reopen показывал 9 окон при 5);
- `create_room` забирает pending-раскладку → первый зритель видит сохранённую
  схему, а не пустую сетку;
- SIP UAS стал opt-in (`VKS_SIP_UAS_ENABLED=1`); dev-юнит включает явно,
  шаблон — нет (закрыт P0 «0.0.0.0:5060 без auth»);
- клиент: превью `260×180` → `320×180` (аспект 16:9 — иконка и композит
  выбирают одинаковую сетку для всех 1..64 окон).

### 1.4 Тесты

`tests/grids.rs` (8): число окон, внутри канваса/без пересечений, 16:9
идеальных галерей, равные ячейки, точные golden-пиксели `vks_grid_g8_m16_5`
@1920 (5 rect'ов), pin (>50% площади, миниатюры 16:9 и меньше), отказ чужих id,
зазоры/поля. Admin: calculate с опциями (поля g/m), `recalc_layout_size` для
`vks_*`. Итог гейта: fmt/clippy/test workspace — зелёные (см. §5).

## 4. Честный бэклог R5 (не сделано)

P0/P1: auth-дыры admin (`GET /conferences/{id}` + PIN, списки без ролевого
гейта); `contact_id` приоритетнее `abonent_id` (фантомное окно у SIP);
фиктивный статус шлюзов; `mode`-эндпоинт перезаписывает preset/size; PG-путь
(`created_at TEXT` vs `Uuid`); нет прод-клиента `LayoutChanged`; `tick_at`
теряет события речи/rekey; self-view затирает жильца; destroy_room на конце
сессии; 17 мс compose под глобальным локом; mёртвые `core_layouts`/legacy
layouts (~600–900 строк); ~45 `VKS_*` вне `Config`; UI-контролы g/m/«Окон»
(~110 строк); пагинация/«+N»/pinOnly/PiP — R6.

P2: `pin` для N<4 визуально хуже галереи (правило «pin 4..8» — продуктовое
решение); бейдж «+N» после WebRTC-моста; независимая сверка golden с .docx
4200 недоступна (нет спецификации); aarch64/rust-src/deny — подтверждено
безвредным.
