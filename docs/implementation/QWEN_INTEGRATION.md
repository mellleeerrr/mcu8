# Совместная работа с локальной моделью qwen3.8-27b-uncensored-code

## Статус (2026-10-23)

Endpoint модели в доступной сети **не обнаружен**: порты 11434 (Ollama), 1234
(LM Studio), 8000/5000 (vLLM/прочее) на 127.0.0.1, 192.168.1.92 и 192.168.1.93
закрыты; `ollama`/`lmstudio` не установлены; в DSH-каталоге провайдеров только
облачные (qwen-token-plan требует ключ). Поэтому мост готов, но фактическая
совместная работа начнётся после того, как владелец задаст адрес.

## Как включить

Любой OpenAI-compatible сервер (Ollama, LM Studio, vLLM, llama.cpp server):

```bash
export QWEN_BASE_URL=http://<host>:<port>/v1
export QWEN_MODEL=qwen3.8-27b-uncensored-code
export QWEN_API_KEY=<если требуется>
./scripts/qwen.sh "ping"          # проверка
```

Скрипт `scripts/qwen.sh`:
- собирает `chat/completions` (temperature 0.2), таймаут `QWEN_TIMEOUT` (120 с);
- печатает только текст ответа; `--raw` — весь JSON; `--system "..."` — системный промпт;
- коды: 2 — нет `QWEN_BASE_URL`/промпта, 3 — сеть/HTTP, 4 — некорректный JSON.

## Протокол «второе мнение» для агентов

1. Перед решением спорного места агент вызывает `scripts/qwen.sh` с коротким
   вопросом (≤2000 символов) и сохраняет ответ в
   `.work-tmp/agents/<agent>/qwen-<step>.json` (`--raw`).
2. В отчёте агента — раздел «Мнение qwen»: ответ модели + расхождения с решением
   Lead; при разногласии Lead обязан либо принять аргумент, либо обосновать отказ.
3. Если endpoint недоступен, агент фиксирует это в отчёте и продолжает без модели
   (не блокирует цикл).

## Ограничения

- Не отправлять `vks_data.db`, дампы, токены и персональные данные.
- 27B на CPU отвечает медленно: таймаут 120 с, промпты короткие.
- Модель не имеет доступа к файлам: передавать нужные фрагменты кода в промпте.
