## 2. Целевая архитектура R5 (полная цепочка библиотеки)

Библиотека meeting-grid-layout — это DOM-движок плиток: галерея с адаптивными
рядами, PIN (крупный + лента), pinOnly, зазоры/поля, пагинация «+N more» при
переполнении, смешанные аспекты, motion. Для MCU-композитора (пиксельные rect'ы
на холсте 1920×1080) это отображается так:

| Концепт библиотеки | В MCU-цепочке |
|---|---|
| gallery, adaptive rows | уже есть (`grids::gallery`) |
| pin / pinOnly | `pin`; `pinOnly` = лента скрыта (1 окно + «+N») |
| gap / margin | параметры геометрии: `cellW=(W-2M-(cols-1)G)/cols`, аналогично H |
| pagination («+N more») | переполнение: окон больше слотов → лишние участники не в композите (метрика), страница = набор слотов |
| mixed aspects | адаптация под аспект холста (формула от W/H, не от фиксированных px) |
| motion | в MCU не применим (кадр = пиксели); в UI — CSS-переходы превью |

Контракт: всё кодируется в параметрическом id (единственное, что переживает
вендорский маппер сохранения) + геометрия из id на сервере. Грамматика:
`vks_<family>[_<opt>...]_<n>`, последний сегмент — число окон (требование
вендорского `Iee`), опции: `g<px>` gap, `m<px>` margin, `p` pinOnly.
Примеры: `vks_grid_9`, `vks_grid_g12_9`, `vks_grid_g12_m24_9`,
`vks_pin_r_g8_7`, `vks_pin_l_m16_p_5`.

Слои:
1. `vks-layout/src/grids.rs`: `GridOptions{gap,margin,pin_only}`, `parse`,
   `geometry_for(scheme, opts, w, h)`; инварианты: покрытие без пересечений,
   зазоры G/M — «чёрные» области холста, ячейки одинаковы.
2. `vks-admin`: `calculate` принимает id (опции уже внутри), `mode` не
   подменяет `vks_*`; `presets`-каталог может отдавать конструктор отдельной
   секцией (id, title, windows) — источник для UI.
3. `vks-server`: `apply_layout` — id → `grids::geometry(1920,1080)` (уже);
   добавить валидацию переполнения (slots > cells → warn+метрика).
4. Клиент: (а) пункт «Конструктор» в `.layout-mode-selector` (классы
   `.layout-mode-selector-item`, `data-qa="layout-mode-selector-constructor"`,
   текст «Конструктор», описание), активное состояние синхронизировано с
   store; клик = ручной режим + показ секции конструктора; (б) сама секция
   конструктора (есть с R4) получает контролы gap/margin/pinOnly в вендорских
   классах; (в) превью — через `calculate`.
5. Тесты: инварианты галереи/PIN с G/M/pinOnly на 1280×720 и 1920×1080;
   golden для опций; API-тесты calculate/mode/apply; e2e live-прогон.

## 3. Гигиена/оптимизация бэкенда (параллельные направления)

- chain-1 layouts: единицы `payload.canvas`, attach/detach x/y, mode-switch.
- chain-2 admin: auth на GET/PIN, PATCH `/profile`, `/sessions/{id}`, 409, конверт.
- chain-3 media: WebRTC-мост MCU→браузер, глобальный Mutex, ffmpeg пул, PLI,
  resize, self-view (R6–R8 отчёта R4).
- chain-4 gateways: source_latch, статус, SIP UAS opt-in, MAX_PEERS, мост.
- chain-5 signaling/storage: WS-envelope, persistence, миграции, конфиги (cat).
- regressions: R5 относительно R4.
- tests-reviewer: оценка тестов 1–10 после R5.

## 4. Порядок работ

1. Агенты (параллельно): layouts-full, mcu-deep, admin, media, gateways,
   signaling/storage, regression.
2. Реализация: `grids` options + id-грамматика + тесты; пункт «Конструктор»;
   превью/apply; live.
3. Сабагент code-review тестов (1–10); второй круг контраргументации.
4. Документ-отчёт R5: реестр агентов (промпт/итог/разногласие/мнение Lead),
   пошаговый план до версий пакетов, честный бэклог.
