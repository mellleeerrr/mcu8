## §3. Список проблем (P0/P1/P2)

### P1-1. DTMF: «200 мс» не доставляются — E-бит выставлен с 3-го пакета
`crates/vks-server/src/gateway_audio.rs:458` (и таблица `:683`, тест `:943–950`).

```rust
event_packet[13] = if step >= 2 { 0x8a } else { 0x0a };   // E=1 начиная с 3-го пакета
let duration = DTMF_DURATIONS[step.min(DTMF_DURATIONS.len() - 1)]; // ...и до 10-го
```
RFC 4733 §2.5.1.4: E=1 ставится **только в последнем** пакете события; получатель, уважающий E-бит,
завершает тон по `duration` первого пакета с E=1 → тон длится ~60 мс (480 сэмплов), а не 200 мс.
Строка `0x8a` — pre-existing, но именно на неё опирается новый заявленный результат, а тест
`:943–949` сравнивает `DTMF_DURATIONS` **сам с собой** и провод не проверяет. То есть «10 пакетов ×
20 мс = 200 мс» доказано только для массива констант.

**Минимальная правка:** `let end = step + 1 == DTMF_DURATIONS.len(); event_packet[13] = if end { 0x8a } else { 0x0a };`
и вынести сборку пакета в `fn dtmf_packet(...) -> [u8; 16]`, тест — на 10 пакетов, `E=1` только у
последнего, `duration` последнего = 1600.

### P1-2. `calculate` отдаёт 400 на `preset_default_13`, а e2e требует ровно один такой 400
`crates/vks-admin/src/api_v3/shell.rs:726`, `tests/e2e/layout_constructor_ui.js:98,138,311`.

Проверено прогоном (линковка с собранным `libvks_layout`):
```
is_known_preset(preset_default_13) = false
is_manual_preset(preset_default_13) = false
preset_size(preset_default_13)      = Some(13)
preset::geometry(preset_default_13) -> 13 slots, first = {x:0,y:0,w:320,h:180}
```
То есть крейт раскладок **умеет** строить геометрию `preset_default_13` (это канонический пресет
«Общей», `preset.rs:647`), а HTTP-эндпоинт объявляет его невалидным (`is_known_preset` = manual ∪ codian,
`preset.rs:681`). Вендорский авто-превью конструктора спрашивает именно этот id → 400 + `reportError` на
каждом открытии. E2E закрепляет это как «400 по контракту сервера» и требует `vendor400Count === 1`
и `reported.expected === 1`, т.е. **исправление сервера ломает тест** — это ложнозелёный оракул
наоборот, ложно-красный.

**Минимальная правка:** в `video_layouts_calculate` принимать любой `PresetId::parse`-известный id
(`if !grid && PresetId::parse(preset_name).is_none() { 400 }`) и отдавать `preset::geometry`;
в e2e заменить `vendor400Count === 1 && reported.expected === 1` на
`pageErrors.length === 0 && reported.unexpected === 0` (+ синтетический контрольный вызов
`reportError` для проверки, что обёртка установлена), не привязываясь к числу 400.

### P1-3. S6-центрирование меняет геометрию живого MCU-движка, без анализа и теста

### P1-4. Две взаимоисключающие иерархии размера раскладки (attach ≠ PATCH)

## §7. Спорные тезисы для дебатов с Lead

### Т1. «S6/S7/S8 прошли независимое ревью на 9.5»
**Тезис:** вердикт 9.5 выставлен коммитом `d82ce4d` («S6/S7/S8 all pass independent review at threshold
9.5»), который тем же изменением правит `grids.rs`, README и LAYOUT_ENGINE. В репозитории нет отчёта
ревьюера, нет списка findings с ссылками и нет автора, отличного от автора правок.
**Доказательство:** `git show --stat d82ce4d` (4 файла, включая код и аудит-строку), отсутствие
отдельного review-артефакта в `docs/audit/**`; моё ревью даёт S6 7.5, S7 7.0, S8 8.0.
**Что переубедит:** отчёт независимого ревьюера (дата, диапазон, findings P0/P1 и их закрытие) или
сырые логи/чек-лист с отрицательными контролями по каждому пункту. Без этого «9.5» — самооценка.

### Т2. «DTMF-тон теперь 200 мс»
**Тезис:** длительности 10×160 сэмплов сами по себе ничего не дают, пока E-бит выставлен с 3-го пакета
(`gateway_audio.rs:458`): RFC 4733 §2.5.1.4 требует E=1 только в последнем пакете, иначе получатель
завершает тон по первому E=1 (≈60 мс). Тест `:943–949` проверяет константу против константы.
**Доказательство:** цитата строки 458, семантика E-бита, отсутствие теста на 16-байтовый пакет;
`git diff 8116855` показывает, что строка `0x8a` не менялась, т.е. «до/после» на проводе одинаково.
**Что переубедит:** запись RTP-потока с реального шлюза (pcap) с длительностью тона 200 мс у
получателя, уважающего E-бит, или тест, который собирает пакеты и проверяет E/duration.

### Т3. «E2E-оракул не фиктивен и не подгоняет результат»
**Тезис:** по механике — да, оракул сильный (неизменяемый `reportError`, `exposeBinding`, axios-provenance).
Но он **закрепляет серверный дефект**: `calculate(preset_default_13)` → 400 при том, что
`preset::geometry("preset_default_13")` отдаёт 13 валидных окон (`preset.rs:647`), и требует ровно
один такой 400 (`layout_constructor_ui.js:311`). Исправление эндпоинта сделает тест красным.
**Доказательство:** прогон с линковкой `libvks_layout` (`is_known_preset=false`, `geometry=13 slots`);
`grep` по e2e (`vendor400Count === 1`, `reported.expected === 1`).
**Что переубедит:** решение Lead'а «400 на `preset_default_13` — намеренный контракт» с обоснованием,
почему `preset::geometry` для этого id существует; либо правка e2e на `unexpected === 0`.

### Т4. «S6-центрирование касается только конструктора/превью»
**Тезис:** `GridLayout::compute` — fallback живого движка (`engine.rs:714`, `regrid_for_video`;
`:277`), поэтому центрирование меняет видеостену: для 5 участников нижний ряд 2×426 px по центру,
заполнение 83.3 % (прогон на HEAD), 16.7 % чёрного. Ни одного теста движка на `n % cols != 0` нет.
**Доказательство:** вывод прогона `GridLayout n=5 @1280x720` (5 окон, area 767520/921600),
`grep -c "regrid_for_video"` в тестах = 0.
**Что переубедит:** продуктовое решение «центрирование распространяется на видеостену» + тест движка,
фиксирующий площадь/положение; либо ограничение изменения только `grids::gallery`.

### Т5. «Ёмкость пресета — источник истины о размере»
**Тезис:** так написано в `derived_layout_size` (`resources.rs:389`), но `layout_size` (`:374`)
ставит `payload.size` выше пресета, и именно её использует attach (`:962`). На legacy-записи из БД
(recacl на загрузке не вызывается — только `normalize_resource`/`update_resource`) это даёт 409
«Layout is full» при живых 25 окнах и расхождение с PATCH, который валидирует по пресету.
**Доказательство:** два порядка в двух функциях, тест `pnm_layout_size_prefers_explicit_size_over_preset`
(`resource_tests.rs:2495`) — `{"preset":"vks_grid_25","size":7} → Some(7)`; `grep recalc_layout_size`
не находит вызова на load.
**Что переубедит:** доказательство, что записей со `size ≠ ёмкость пресета` не бывает (миграция/инвариант
БД + тест), либо единый резолвер в коде.

### Т6. «0 пересечений / 0 выходов — доказанный инвариант»
**Тезис:** верно только для целевого холста 1280×720 (и то при `n % cols == 0` для покрытия).
Для `calculate(width=9, height=10, preset=vks_grid_100)` окна уходят за холст по Y до 20 при height=10
(`.max(1.0)` в `gallery`), пересечений при этом нет. Утверждение `04_geometry.md:27` «0 пересечений,
0 выходов … все режимы и размеры» — ложно; инварианты в `tests/grids.rs` проверяются только на 1280×720.
**Доказательство:** вывод прогона `vks_grid_100 @9x10 → max=(9,20)`; `grep -n "for count in 1..=100"` в
тестах и константы `W/H = 1280/720`.
**Что переубедит:** ограничение входа `calculate` (`width,height >= 64`) с тестом на 422 — тогда
утверждение нужно переформулировать как «для холстов ≥ 64 px».

### Т7. «CI закрывает дрейф UI-артефактов»
**Тезис:** частично. `frontend-integrity` проверяет MANIFEST (214/214), `patch --check` и
`unittest test_pnm_patch_lib`; но ни e2e-конструктор (20 проверок), ни geometry parity в CI не
запускаются (`grep "playwright\|node tests/e2e"` по `ci.yml` → пусто). «20/20» из аудита —
ручной прогон, который нельзя воспроизвести в PR.
**Доказательство:** содержимое `ci.yml:255–271`; отсутствие Playwright-джобы.
**Что переубедит:** джоба с Playwright на эфемерном инстансе (или явная строка в аудите
«e2e manual-only, gate не является») — тогда тезис сузится до «артефакты закрыты, поведение нет».

### Т8. «49/49 ok — доказательство зелёного workspace»
**Тезис:** 49 — это количество `test result`-блоков (test-бинарников), а не тестов. Реальный прогон на
HEAD: **1425 passed / 0 failed / 8 ignored**. Формулировка вводит читателя аудита в заблуждение и
скрывает 8 ignored (среди них — ручные и сетевые), из-за чего «manual-only» неотличим от «спрятан».
**Доказательство:** `grep -c "^test result" /tmp/t_ws.log` = 49; сумма passed = 1425, ignored = 8.
**Что переубедит:** признание формулировки неточной и правка строки S11 на реальные числа
(это дешёвая правка, и её отсутствие показательно).
