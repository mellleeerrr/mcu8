### 1.2 Шесть самых дорогих расхождений (что чинит T04b)

1. **G.729 живёт в трёх несовместимых состояниях:** SIP честно отказывает 488 (strict-first, `rtp_bridge.rs:1403-1443`), в `AUDIO_OFFER` лежит мёртвая строка, `H323CodecMap` **считает его принятым** и обещает транскод в Opus (`h323/src/codec.rs:100, 111-124`, тесты `call.rs:441-442`), а реальный сайдкарный путь отвергает (`uac.rs:139-146`). Причины в доках две разные: «нет энкодера» и «не bit-exact».
2. **H.264 не имеет измерения «профиль»** в типе возможностей: `is_native_video` не может выразить «RX High / TX baseline», поэтому `H264-HIGH` в настройках — это `supported:false` (правильно), но той же функцией проверяется и то, что реально работает на RX. Плюс `offer_video_enabled` **fail-open** (`:512-518`, default `_ => true`; тест `:1526` это закрепляет).
3. **Семь мёртвых строк оффера** (18, 102-106, 112) не объявляются, но **нужны** для fail-closed ответа (см. ловушку T2) — их нельзя ни удалить, ни «почистить» без переделки резолва.
4. **PT-истина размазана на четыре карты** (`AUDIO_OFFER`, `uas` static, `bridgeable_audio_pts`, `audio_codec_name`): PT2 есть в двух из четырёх, PT113 — в двух, причём `audio_codec_name(113)` возвращает имя даже когда AAC выключен (`gateways.rs:1042` против `:1009`).
5. **Две частоты под одним словом «clock»:** G.722 — RTP clock 8000 (`rtp_bridge.rs:290`, `uas.rs`), но sample rate 16000 (`gateways.rs:989`); AAC-LATM — RTP clock 90000, sample rate 48000 (`gateways.rs:990`). Один тип с одним полем это гарантированно перепутает.
6. **Нормализация имени в четырёх копиях** с разными наборами разделителей: `codec_capabilities.rs:72-74` (`. - _ `), `uas.rs:551` (`. - _`), `gateway_audio.rs:44-46` (`. - _`), `gateway_aac.rs:81`. `"MP4A-LATM "` проходит в одной ветке и падает в другой (аудит 03, D7).

## §2 Минимальная форма SSOT

### 2.1 Модуль и типы

Новый файл `crates/vks-common/src/codec_spec.rs`; `codec_capabilities.rs` остаётся **фасадом** с теми же именами функций (все 25 существующих вызовов `vks_common::codec_capabilities::*` не меняются). Новый крейт/зависимость не нужен.

```rust
//! codec_spec.rs — единственная таблица кодеков. SDP-детали (payload type,
//! rtpmap/fmtp, порядок m=) сюда НЕ входят: они живут в vks-gateway-sip.
//!
//! | id | SIP | H.323 | WebRTC | лицензия | причина |

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum CodecKind { Audio, Video, Dtmf }

/// Плоскость продукта. Диспозиция у одного кодека может быть разной:
/// VP9 — WebRTC-only, G.728 — SIP-only.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Transport { Sip, H323, WebRtc }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Disposition {
    /// Кодируем и декодируем в обе стороны.
    Implemented,
    /// Принимаем от пира; отдать не можем (энкодер другого профиля).
    ReceiveOnly,
    /// Мост готов, включается только явным решением оператора.
    LicenseGated,
    /// Нет реализации (энкодера/пейлоадера) — объявлять нельзя.
    Rejected,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum License {
    Free,
    /// Идентификатор для `VKS_CODEC_LICENSE_ACCEPTED` (например "aac-latm").
    OperatorOptIn(&'static str),
    /// Нужно соглашение с правообладателем (Polycom), флага недостаточно.
    AgreementRequired(&'static str),
}

pub struct CodecSpec {
    /// Уникальный ключ в нормализованной форме: "G722", "G72632", "MP4ALATM".
    pub id: &'static str,
    /// Отображаемое имя (совпадает со строками настроек): "G722", "G726-32".
    pub name: &'static str,
    /// Реальные алиасы из настроек/доков: `&["G7231"]`, `&["G711","G711U","G711A"]`.
    pub aliases: &'static [&'static str],
    pub kind: CodecKind,
    /// RTP clock для rtpmap/таймстампа: G722 = 8000, MP4A-LATM = 90000.
    pub rtp_clock: u32,
    /// Частота дискретизации для микшера/ресемплера: G722 = 16000.
    pub sample_rate: u32,
    /// Каналы в rtpmap (Opus = 2, остальные 1; видео 0).
    pub channels: u8,
    /// Статический PT RFC 3551, если он есть (0,8,9,15,4,18; у G.726-32 = 2).
    /// Наш динамический PT выбирает SIP-крейт — здесь его нет.
    pub static_pt: Option<u8>,
    pub sip: Disposition,
    pub h323: Disposition,
    pub webrtc: Disposition,
    pub license: License,
    /// Причина для SIP/UI-плоскости; `""` ⇔ `sip == Implemented`.
    /// Для H.323/WebRTC причины держит соответствующая плоскость.
    pub reason: &'static str,
}
```

Причины — константы (машиночитаемый id + человеческая строка рядом), чтобы UI и тесты не сравнивали прозу:

```rust
pub mod reason {
    pub const NO_IMPLEMENTATION: &str = "no_implementation";          // "no codec implementation: neither FFmpeg nor oxideav"
    pub const ENCODER_NOT_BIT_EXACT: &str = "encoder_not_bit_exact";  // "encoder exists but is not bit-exact against ITU vectors"
    pub const LICENSE_NOT_ACCEPTED: &str = "license_not_accepted";    // "license not accepted by operator (VKS_CODEC_LICENSE_ACCEPTED)"
    pub const WEBRTC_ONLY: &str = "webrtc_only";                      // "SIP terminals do not offer it; no RTP payloader"
    pub const TX_PROFILE_UNSUPPORTED: &str = "tx_profile_unsupported";// "gateway encoder is baseline-only: receive-only"
    pub const PENDING_PAYLOADER: &str = "pending_payloader";          // "RFC 4629/4587 payloader not implemented"
    pub const SVC_UNSUPPORTED: &str = "svc_not_forwarded";            // "str0m has no SVC-forwarding API"
}
```

API (все — `#[must_use]`, без аллокаций в горячем пути, кроме `*_names`):

```rust
pub static CODECS: &[CodecSpec];

pub fn spec(name_or_alias: &str) -> Option<&'static CodecSpec>;  // единственная normalize()
pub fn normalize(name: &str) -> String;                          // переезжает из codec_capabilities.rs:72
pub fn disposition(name: &str, transport: Transport) -> Option<Disposition>;
pub fn reason_of(name: &str) -> &'static str;                    // "" если Implemented
pub fn is_implemented(name: &str, transport: Transport) -> bool; // == Implemented
pub fn native_names(kind: CodecKind, transport: Transport) -> Vec<&'static str>; // генерируемый срез
pub fn license_opt_in_id(name: &str) -> Option<&'static str>;    // Some("aac-latm") для AAC
```

### T2. Удаление «мёртвых» строк оффера ломает fail-closed (главная ловушка)

`remote_audio_identity` (`rtp_bridge.rs:1224-1232`) резолвит имя пира **через `AUDIO_OFFER`**. Если убрать строки 18/102-106/112:

- ответ `RTP/AVP 18` + `a=rtpmap:18 G729/8000` перестанет быть «известным отказом» → payload пропускается → следующим выбирается PT0 PCMU → **молчаливое понижение вместо 488**;
- тест `:1640-1651` упадёт, и «починить» его будет соблазн ослабить.

Следствие для метатеста: он **не может** требовать «у каждого rejected-кодека нет строки» или «у каждой строки disposition == Implemented». Правильные инварианты:

1. каждая строка `AUDIO_OFFER`/`VIDEO_OFFER` имеет `spec(row.name)` (сравнение через `normalize`);
2. `row.native == (spec.sip == Implemented) and codec != dtmf` (уже почти есть в `:863-876`);
3. `spec.sip == Rejected` ⇒ строка **обязана существовать** (иначе fail-closed теряется) и **обязана не попадать** ни в Native-, ни в Full-оффер;
4. `spec.sip == Implemented` ⇒ ровно одна строка (ровно один оффер).

### T3. `offer_video_enabled` fail-open

`rtp_bridge.rs:512-518` возвращает `true` для любого неизвестного имени (`H261`, `H263`), и тест `:1526` это **закрепляет**. Когда в SSOT появятся видео-спеки с `Rejected`, достаточно одной строки в `VIDEO_OFFER`, чтобы H.261/H.263/VP9 ушли в SDP без probe. Фикс: `_ => false` + гейт по `spec.sip == Implemented`; тест `:1526` обновить на `assert!(!offer_video_enabled("H261", true, true))`. Это изменение поведения, его нужно назвать в PR явно.

### T4. `clock` — два разных смысла (RTP clock ≠ sample rate)

- G.722: `rtp_clock = 8000` (`rtp_bridge.rs:290`; RFC 3551 §4.5.2), но `audio_sample_rate_for_codec("G722") == 16000` (`gateways.rs:989`) и mixer/frame_samples 320 (`gateway_audio.rs:86`).
- MP4A-LATM: `rtp_clock = 90000` (RFC 3016), sample rate 48000.
- telephone-event: clock 8000 **обязан** быть равен clock медиа-секции (`uas.rs:306`).

Один `clock` в `CodecSpec` — гарантированный регресс (TE-таймстампы, тик микшера). Нужны оба поля + тест-инвариант `G722.rtp_clock == 8000 && G722.sample_rate == 16000`.

### T5. PT2 (G.726-32) и PT113 (AAC) — асимметрия, которую легко сломать

- PT2 **отсутствует** в `AUDIO_OFFER` (есть только 107-110), но присутствует в `bridgeable_audio_pts` и `audio_codec_name`; исходящий путь спасает только `remote_audio_identity`-fallback по имени. Если «сгенерировать» PT-список из `AUDIO_OFFER`, PT2 исчезнет → регресс T04a (D5).
- PT113: в `audio_codec_name` он **безусловно** (`gateways.rs:1042`), в `bridgeable_audio_pts` — условно (`:1009`). Значит `audio_codec_name` — не авторитет доступности; нельзя делать `supported` из него.
- Вывод: PT-список и PT→имя должны строиться из одного источника (`AUDIO_OFFER` + явные константы `G726_32_LEGACY_PT = 2`), а не из двух независимых `match`.

### T6. Лицензионный гейт нельзя размазать

Сегодня доступность AAC = **одно** `AtomicBool`, вычисленное в `main.rs:390-403` как `legal && pool>=2 && probe`. Тесты полагаются на «probe off by default» (`codec_capabilities.rs:213-219, 234-239`, admin `tests.rs:379-405`). Если `CodecSpec` начнёт сам читать env или добавлять второй чек (`license_required` + отдельный флаг), получим:

- расхождение «UI supported=true, SDP без 113» (или наоборот);
- падение common-тестов, которые гоняются без сервера;
- wasm-проблему (env недоступен).

Правило: `CodecSpec::license` — **декларация**; runtime-решение остаётся в `audio_codec_available()`/`codec_policy`.

### T7. wasm-совместимость `vks-common`

`crates/vks-common` — прямая зависимость WASM-SDK (`client/vks-client-sdk/Cargo.toml:23`), CI гоняет `cargo check -p vks-client-sdk --target wasm32-unknown-unknown`. Ограничения для новой таблицы:

- только `&'static [CodecSpec]` из `Copy`-скаляров и `&'static str`/`&'static [&'static str]`;
- никаких `HashMap`, `OnceLock`+env, `Mutex`, `std::time` при инициализации;
- `AtomicBool` уже используется и на wasm безопасен (single-thread).

### T8. Зависимости

`crates/vks-common/Cargo.toml:11-23` — фиксированный набор; `deny.toml` банит лишнее. `CodecSpec` не должен требовать новых крейтов; `serde` derive не нужен — админка сериализует через `json!`.

### T9. H.323-контрадикция G.729: исключить из метатеста явно

`H323CodecMap::is_audio` принимает `G729` (`h323/src/codec.rs:100`), а `for_codec` отправляет **любой** H.323-аудио в `OPUS` с `needs_transcode=true` (`:111-124`). Реальный путь — только симметричные PT `0/4/8/9` (`uac.rs:139-146`, `gateways.rs:1017-1020`). Если метатест «каждая rejected-спека не принимается на плоскости» пройдётся по `h323/codec.rs`, зелёным он станет двумя способами: (а) удалить G.729 из `codec.rs` (правильно, но ломает `call.rs:441-442`, `codec.rs:200-260`), (б) расширить реальный мост (катастрофа). Поэтому: либо `codec.rs` целиком вне метатеста с комментарием «dead WebRTC model, §6 аудита 03», либо отдельный коммит на его удаление **после** T04b.

### T10. Алиасы и нормализация

- `G7231` отсутствует в `NATIVE_AUDIO`, но принимается UAS (`uas.rs:591-601`) и H.323 (`H323_AUDIO:125`). В SSOT это `aliases: &["G7231"]`.
- `G711/G711U/G711A` — алиасы PCMU/PCMA без собственных PT: должны резолвиться в `PCMU` (или `PCMA` для `G711A`), иначе `ensure_bridgeable_codec_selection` (`gateways.rs:147-190`) начнёт отвергать валидные настройки.
- Единая `normalize` (`. - _ ` + uppercase) переносится в `codec_spec`; копии в `uas.rs:551`, `gateway_audio.rs:44-46`, `gateway_aac.rs:81` удаляются. SDP-имена пробелов не содержат — снятие пробелов безопасно.
- Сравнение с `AUDIO_OFFER` — **только через normalize**: в оффере `opus` строчными (тест `:985` это фиксирует), в SSOT — `OPUS`.

### T11. Публичный API `NATIVE_AUDIO`

`pub const NATIVE_AUDIO` читают 4 места (`shell.rs:288-289`, `gateways.rs:152-157`, тесты `codec_capabilities.rs:165-189`, `rtp_bridge.rs:863-876`); внешних потребителей нет (проверено grep по `crates/` и `client/`). Решение: удалить константы и отдать `native_names()`, мигрировав 4 места в одном коммите. Оставлять константу «для совместимости» нельзя — это и есть второй список.

### T12. Профили H.264: не сворачивать в один id

`is_native_video("H264-HIGH") == false` закреплено тестом `codec_capabilities.rs:186-188`, а настройки содержат `H264-HIGH`, `H264-SVC` (`settings.rs:66`). Один `H264` с `Implemented` не выразит «RX High/TX baseline», а `H264-HIGH.Implemented` сломает публичную матрицу. Нужны отдельные спеки `H264MAIN`/`H264HIGH` с `ReceiveOnly`, и `is_native_video` остаётся «SIP-Implemented» (для H264-HIGH — false).

### T13. `--all-features` уже красный

По `00_MASTER_PLAN.md` §1 `cargo test --workspace --all-features` падает на 2 тестах `vks-media-sfu::codec::tests::*` (зашиты под default-набор фич). Не включать `--all-features` в приёмку T04b и не пытаться «попутно починить» — это T03. Гонять по-крейтово.

### T14. Порядок причин в UI

Админка сегодня отдаёт только `supported: bool` (`shell.rs:579`). Добавление `reason`/`disposition` меняет форму JSON — вендорский UI (`/mcu/*.js`) читает поля терпимо, но `api_v3/tests.rs:387-404` ищет строго `codec["supported"]`. добавлять поля, не переименовывая существующие.
