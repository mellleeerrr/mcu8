## §1. Что именно называется «легаси-плоскостью» (точный инвентарь)

### 1.1. Определение

Легаси-плоскость — это **plaintext-RTP MCU/SFU без DTLS/SRTP** плюс **рукописный SDP-ответ с фиктивными ICE/DTLS-кредами**, который эта плоскость отдавала браузеру. Она не является «старым кодом вообще»: это конкретная цепочка «offer → `SfuAnswerProfile` → `Payload::SdpAnswer` → plaintext UDP → `SfuEngine::route_udp_packet` → `Forwarder` → `UdpMediaLoop::send_raw`».

Состав:

1. **Переключатель и fallback.** `webrtc_runtime.rs:23-30` — `enabled()`; при `false` оффер получает фиктивный ответ, при `true` — fail-closed.
2. **Plaintext-путь.** `vks-media-sfu`: `udp_loop.rs` (STUN-ответчик, классификатор RTP/RTCP, PLI), `engine.rs` (`route`, `register_endpoint`, `register_ssrc`, `route_udp_packet`, `generate_pli_for_room_publishers`), `forwarder.rs`, `bwe.rs`, `congestion.rs`, `simulcast.rs`, `dtls.rs` (mock-ключи), `ice.rs` (mock host candidates), `codec.rs` (реестр/парсеры без продакшн-потребителя).
3. **Фиктивный SDP.** `HandlerConfig.ufrag/pwd/fingerprint/candidate_addr/candidate_port` (`handler.rs:26-45`), `answer_profile()` (`:139-168`), `on_sdp_offer` (`:344-373`), `SdpAnswerProfile`/`sfu_answer`/`with_ice_candidates` (`sdp.rs:415-570`).
4. **Серверные легаси-эффекты.** Регистрация endpoint/SSRC/PT, PLI через UDP-луп, `real_webrtc_peer`-ветвления (`lib.rs:687-688, 1019, 1107-1149, 1216-1218, 1308-1310`).
5. **Конфиг/метрики.** `media_listen_addr` (`config.rs:42-43`), `WEBRTC_FALLBACK{reason="disabled"}` (`metrics.rs:90-93`, тест `:260`).

## §2. Что сломается, если `VKS_WEBRTC_TRANSPORT` станет обязательным

### 2.1. Семантика, которую надо зафиксировать

Сейчас `enabled()` — трёхзначная логика с fail-open: unset → `true`; `0/false/off/no` → `false`; любой мусор (`"garbage"`, `"2"`, `"trueish"`) → `true` (потому что не совпал с false-списком). Это и есть главный дефект «mandatory»: **опечатка включает транспорт, а не выключает**.

Предлагаемый контракт (обосновать в ADR/доке):

| Значение | Сейчас | Должно быть |
|---|---|---|
| не задано | `true` | **startup error 78** (`VKS_WEBRTC_TRANSPORT is required`) |
| пусто/пробелы | `true` | **startup error 78** |
| `1`,`true`,`on`,`yes` (case-insensitive, trim) | `true` | единственный допустимый режим — transport on |
| `0`,`false`,`off`,`no` | `false` (legacy) | **startup error 78** (`legacy plane removed; there is no off switch`) |
| любой другой мусор | `true` | **startup error 78** |
| `VKS_WEBRTC_TRANSPORT` + `VKS_CANDIDATE_ADDR` пуст | legacy fake SDP | **startup error 78** (missing candidate) |

Это делает «on by default» и «mandatory» совместимыми только в одной трактовке: **дефолта больше нет, есть единственное валидное состояние — on**. Тест «transport on by default» должен проверять именно это (`None` → ошибка, а не тихое `true/false`); иначе формулировка задачи противоречива.

**`allow_insecure_defaults` не освобождает от mandatory env.** Он разрешает только loopback/unspecified candidate (`webrtc_runtime.rs:59-66`, `main.rs:426`) и dev-секреты; `VKS_WEBRTC_TRANSPORT` обязателен и в dev, и в prod. Иначе получится «в dev можно без env, в prod нельзя» — два разных контракта запуска, и e2e/CI разойдутся с боем. Dev-конфиг уже содержит явный `candidate_addr = "127.0.0.1"` (`configs/default.toml:20`), поэтому `cargo run` требует только env, а не послабления candidate.

### 2.4. Миграция живого/продового запуска

1. До деплоя: проверить `/etc/vks/vks.env` (или drop-in) на `VKS_WEBRTC_TRANSPORT=1`; иначе добавить. Для установленного прод-юнита — активная строка `Environment=` как страховка.
2. Smoke/второй процесс: `VKS_WEBRTC_TRANSPORT=1` + **другой** `VKS_WEBRTC_PORT_MIN/MAX` (или эферные), иначе конфликт с боевым 43000–43100. Preflight транзиентный bind+drop конфликт **не поймает**.
3. `RestartPreventExitStatus=78` уже есть — сервис не зациклится, но и не поднимется; в runbook добавить «exit 78 → проверь `VKS_WEBRTC_TRANSPORT`/candidate».
4. Порт 40000 после рестарта свободен; проверить firewall/мониторинг/T15, которые могли считать его медиа-листенером.
5. Откат T11c — только возврат предыдущего бинаря/коммита; `VKS_WEBRTC_TRANSPORT=0` больше не откат.

## §6. Чего НЕ делать

1. **Не удалять `webrtc.rs`/`webrtc_room.rs`** и их 17 тестов — это единственная реальная плоскость.
2. **Не удалять `vks-media-mcu`, SIP/H.323-шлюзы и guard'ы `room_has_peer`** — это T12, не T11c.
3. **Не трогать `MAX_PEERS_PER_ROOM=2`** и per-source mid — T11b.
4. **Не оставлять легаси «для тестов»** (`#[cfg(test)] mod legacy`, `SfuEngine` как test-only): план прямо запрещает; иначе плоскость воскресает.
5. **Не делать env-дефолт в коде** (`unwrap_or("1")`) — mandatory означает явное значение; дефолт допустим только в `scripts/run-local.sh` как launcher-контракт, с логом.
6. **Не принимать `0`** как «выключено»: без легаси это старт без медиаплоскости.
7. **Не удалять `VKS_WEBRTC_PORT_MIN/MAX`/preflight-bind** — это T11a и защита от неверного диапазона.
8. **Не оставлять `media_listen_addr` молча-игнорируемым** без deprecation/release note.
9. **Не менять протокол** `SdpOffer`/`SdpAnswer`/`IceComplete`: SDK и PNM-клиент ждут те же сообщения.
10. **Не удалять `WEBRTC_FALLBACK` целиком** без обновления метрик-теста/дашборда; лучше оставить `offer_rejected`.
11. **Не трогать T04b WIP** (`codec_capabilities.rs`, `codec_spec.rs`, `rtp_bridge.rs`) и не делать `cargo clean` (риск потерять release-бинарь/инкрементальный кэш).
12. **Не открывать/не менять** `vks_data.db`, живые порты `:8080`/`:18082`, `backups/`, чужие audit-файлы; все проверки — на temp-копии/БД.
