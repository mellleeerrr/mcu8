## 2. Deep link: почему ломается и как чинить

### 2.1. Что работает, а что нет (эмпирика)

На ephemeral-сервере (`:18097`, свежая БД, live-статика read-only):

1. **Холодный deep link без токена**: `GET /pnm/monitoring/sessions/<id>` → `200 text/html` (SPA fallback), клиент уходит на `/pnm/authorization`. В URL **нет** `?redirect=`/`returnTo` — ID потерян.
2. **Логин**: `POST /api/v3/login` (`admin`/`admin_password`), токен в `localStorage.TrueConfMCU_AccessToken`; после логина URL `/pnm/monitoring/sessions` — **ID потерян**.
3. **С валидным токеном**: deep link остаётся, рендерится `.session-card` = 1, вкладок = 5 — базовая гидрация работает.
4. **С истёкшим токеном**: guard пропускает (проверяет только наличие токена), первый GET сессии → 401 → интерцептор `logout()` + `authorization`. ID снова потерян.
5. **Прототип project-layer** (`deeplink.js`, внешний скрипт до бандла) восстановил deep link и после холодного логина, и после 401: `afterLogin` и `afterReLogin` — целевой URL, `.session-card` = 1, tabs = 5, `sessionStorage` очищен.

### 2.2. Гонка гидрации и авторизации

- Guard (`Sie`, `:1@1217978`) проверяет **наличие** токена, не его валидность. Поэтому протухший токен проходит guard, компонент монтируется, `watch` с `immediate` (`index6:1@976252`) сразу делает GET.
- При 401 параллельно работают два перехода:
  - интерцептор: `logout()` → push `authorization` (`:1@1261057`);
  - `watch.catch`: push `{name:"monitoring-sessions"}` (`index6:1@976285`).
  В пробе победил интерцептор, но порядок не гарантирован. Если `watch.catch` успеет первым, «предыдущий URL» в момент перехода на authorization будет уже списком — сохранение deep link «по факту смены URL» потеряет ID.
- Поэтому сохранять deep link нужно **в момент logout**, до навигации: обернуть `localStorage.removeItem` и при удалении ключа токена зафиксировать текущий `pathname+search`, если он deep-link. Это наблюдение, не изменение поведения; ключ токена не трогаем.
- Восстановление делать **один раз** через 500–700 мс после появления токена (вендор успевает сделать свой push `/monitoring` и дочерние редиректы), с `attempted = true`. Иначе:
  - слишком рано — вендорский push перетрёт;
  - без флага — цикл при несуществующем ID, потому что 404-ветка молча редиректит на список (`:1@1126255`), и скрипт будет «возвращать» битый URL снова.

### 2.3. Почему внешний `deeplink.js`, а не патч бандла

Master plan (`00_MASTER_PLAN.md:186`) предлагает `patch-pnm-auth-deeplink.py` (правка vendor bundle). Это допустимо, но:

- нарушает границу «не менять семантику vendor-ассетов» и требует cache-bust/патч-скрипта/`--check` в CI;
- оставляет 214 файла, а task-list требует **215/215**;
- возрастает риск сломать минифицированный Vue-роутер и существующие patch-скрипты.

Внешний `deeplink.js` в project-layer блоке:
- CSP-совместим (`script-src 'self'`, без inline и без нового хэша);
- загружается **до** `index.bundle` (блок `index.html:29-34`);
- сохраняется импортом как обычный project-layer файл;
- даёт ровно +1 файл → 215.

### 2.4. Контракт `deeplink.js` (прототип проверен)

```
KEY = 'VKS_PNM_RETURN_TO'            // sessionStorage, не localStorage
DEEP = /^\/pnm\/(monitoring\/sessions|history)\/[0-9a-f-]{36}$/i
```

1. На загрузке: если `!token && DEEP.test(location.pathname)` → `sessionStorage.setItem(KEY, path)`.
2. Обернуть `localStorage.removeItem`: если ключ `TrueConfMCU_AccessToken` и текущий path — deep link, сохранить его **до** удаления.
3. Обернуть `history.pushState`/`replaceState`, чтобы проверять состояние после навигаций вендора (не полагаться на `popstate`).
4. `restore()`:
   - нет `KEY` → выход;
   - текущий URL уже целевой → удалить `KEY`, `attempted=false`;
   - нет токена → `authSeenAt=0`, `attempted=false`;
   - токен впервые увиден → `authSeenAt=now`; ждать ≥600 мс;
   - `router = document.querySelector('#root').__vue_app__.config.globalProperties.$router`;
   - `router.replace(pathWithoutBase)` (path уже `/pnm/...`, у router base `/pnm/` — снять префикс);
   - `attempted=true`, один раз; `catch(()=>{})`.
5. Валидация: принимать только `^/pnm/` и UUID; отбрасывать `//evil`, `%2f`, `..`, внешние URL — иначе open redirect.
6. Ошибки — только `console.debug`, без `throw`; файл не должен ломать загрузку UI.

Проверено: холодный логин, 401-истечение, повторный логин; `stored:null` после успеха.

### 2.5. Тесты deep link

**CI-safe (без браузера):**

`Vary: Accept-Encoding` уже стоит (middleware `frontend.rs:204`), но представление всегда identity. `find ... -name '*.gz'` — 0 файлов. `Cargo.toml:64`: `features = ["fs"]`, `CompressionLayer` в коде отсутствует.

Причина: `precompressed_gzip()` (`frontend.rs:85-87`) отдаёт `.gz` **только если файл уже лежит рядом**; `--gzip` (`import-pnm-frontend.sh:303-310`) запускается после генерации манифеста и генерирует файлы, которые `.gitignore:14` не пускает в git. На чистом checkout/деплое `.gz` нет → gzip не работает. Это ровно дефект из master plan.

### 3.2. Решение

1. `Cargo.toml:64`:
   ```toml
   tower-http = { version = "0.6", default-features = false, features = ["fs", "compression-gzip"] }
   ```
2. В `frontend.rs`:
   ```rust
   use tower_http::compression::{CompressionLayer, predicate::{Predicate, SizeAbove}};
   ```
   Предикат:
   ```rust
   let compressible = SizeAbove::new(1024).and(
       |status: StatusCode, _v: Version, headers: &HeaderMap, _e: &Extensions| {
           status == StatusCode::OK && is_compressible(headers)
       },
   );
   ```
   `is_compressible` — allowlist по `Content-Type` (до `;`):
   `text/html`, `text/css`, `text/javascript`, `application/javascript`, `application/json`,
   `application/manifest+json`, `image/svg+xml`, `application/xml`, `text/xml`, `text/plain`.
   **Не** `text/*` целиком и **не** `image/*` целиком: `font/ttf`, `video/webm`, `image/png` жать нельзя.
3. В `Frontend::router()` (`frontend.rs:104-106`):
   ```rust
   self.mount()
       .layer(CompressionLayer::new().compress_when(compressible))
       .layer(axum::middleware::from_fn(with_cache_control))
   ```
   Последний `.layer` — внешний: `Vary`/`Cache-Control` добавляются после компрессии; дублирования `Vary` нет.
4. Убрать `.precompressed_gzip()` из `frontend.rs:85-87` (иначе два механизма и риск stale `.gz`). Тогда:
   - тест `precompressed_gzip_is_served` (`:573`) заменить на gzip-layer тест;
   - `--gzip` (`import-pnm-frontend.sh:303-310`) удалить/пометить deprecated — `.gz` больше не нужны, а их наличие только путает счётчик 215;
   - `.gitignore:13-14` можно оставить (старые файлы не попадут в git), но в NOTES зафиксировать «gzip on-the-fly».
5. `Cargo.lock` обновить **без** `--locked` (появятся `async-compression 0.4.51`, `compression-codecs 0.4.46`, `flate2 1.1.10`, `miniz_oxide 0.9.1`, `crc32fast`, `adler2`, `simd-adler32`, `zlib-rs`), затем закоммитить. Все лицензии в allowlist `deny.toml` (MIT/Apache/Zlib), но `cargo deny check` всё равно прогнать.

### 3.3. Подводные камни gzip

- **HEAD**: `CompressionLayer` с простым closure сожмёт пустое тело HEAD, удалит `Content-Length` и сломает `head_and_if_modified_since` (`frontend.rs:550`). `SizeAbove` проверяет `body.size_hint()` **до** MIME-предиката; у HEAD/304 hint = 0 → пропуск. Поэтому `SizeAbove.and(closure)`, а не «сначала closure».
- **304**: тело пустое, `SizeAbove` пропускает; `If-Modified-Since` продолжает работать.
- **Уже сжатый ответ**: tower-http не сжимает повторно, если есть `Content-Encoding` (важно, если `.gz` всё же остались).
- **Content-Length**: у сжатого ответа его не будет (chunked). `http_metrics_middleware` (`lib.rs:357-365`) считает байты по `Content-Length` → для статики с gzip метрика `vks_http_response_bytes` станет 0. Это P2-регрессия наблюдаемости, не приёмки; задокументировать или считать `content-length` до компрессии.
- **`Accept-Ranges`**: tower-http удаляет его у сжатого представления; для webm/шрифтов (не сжимаются) Range не страдает.
- **Мелкие файлы**: порог 1024 B; `theme-toggle.js` 3 984 B сжимается, `manifest.webmanifest` 1 556 B — тоже; `api-errors.js` ~2.6 KB — тоже. Слишком низкий порог (32 B по умолчанию) даёт лишний CPU на мелочи.
- **Тест-фикстура**: `FIXTURE_HTML` в `frontend.rs:291` крошечный (<1024 B) — наивный тест «/pnm/ → gzip» на фикстуре **не сожмётся**. Нужен фикстурный HTML ≥4 KB или отдельный большой файл.
- **CI `--locked`**: до коммита `Cargo.lock` падают `test`, `test-all-features`, `build`, `deny`, `path-with-spaces` (`ci.yml:129,182,205,282,299`). Это не «флейк», а жёсткий блокер.
- **ADR**: `0027:50,85` описывает precompressed; после T07 обновить на `CompressionLayer`/`compression-gzip`, иначе T03b «docs-to-fact» зафиксирует расхождение.

### 3.4. Тесты gzip

Добавить в `crates/vks-server/src/frontend.rs`:

1. `pnm_index_is_gzip_when_accepted`:
   - фикстура с `index.html` ≥4 KB;
   - `GET /pnm/` + `Accept-Encoding: gzip` → 200, `content-encoding: gzip`, `vary: Accept-Encoding`, `content-length` отсутствует;

## 4. Тема: инвариант `meta theme-color == computed --c-bg`

### 4.1. Замеры

| Сценарий | `html.class` | `meta[theme-color]` | computed `--c-bg` | `body` background |
|---|---|---|---|---|
| headless default (light) | `theme-light` | `#0088CC` | **пусто** | `rgb(248,248,248)` |
| после toggle dark | `theme-dark` | `#0E1621` | `#0e1621` | `rgb(14,22,33)` |

В light инвариант **не выполняется**: `--c-bg` не определён, meta показывает `--c-primary` (`#0088CC`). В dark значения совпадают, но только после выполнения `theme-toggle.js`; статический HTML отдаёт `#0097A7`, а `manifest.webmanifest` — тоже `#0097A7`.

Три независимых писателя meta:
1. статический `index.html:37` — `#0097A7`;
2. `theme-toggle.js:27` — `#0E1621`/`#0088CC`;
3. `assets/manifest.webmanifest:11` — `#0097A7` (это PWA, не DOM meta, но проверки часто путают).

### 4.2. Минимальная правка

1. `index.html` после dark-блока (после `:296`):
   ```css
   html.theme-light { --c-bg: #f8f8f8; }
   ```
   `#f8f8f8` — фактический вендорный light-canvas (проверено computed body). Полный набор light-токенов не добавлять: это отдельная миграция.
2. `index.html:37`: `content="#0e1621"` — статический дефолт совпадает с dark `--c-bg`; при light тоггл перепишет до первой отрисовки (скрипт синхронный в `<head>`).
3. `theme-toggle.js:26-27`:
   ```js
   var bg = getComputedStyle(root).getPropertyValue('--c-bg').trim();
   if (meta) meta.setAttribute('content', bg || (isDark ? '#0e1621' : '#f8f8f8'));
   ```
   Читать **после** `classList.toggle` (`:24-25`), иначе получится старое значение.
   Тонкость: первый `apply()` (`theme-toggle.js:39`) выполняется **до** блока `<style id="prostor-pnm-dark-theme">` (`index.html:262`), поэтому `getComputedStyle` на первом вызове вернёт пусто — fallback-константы обязательны; повторный `apply()` в `mount()` (`:55`) уже видит токены. Никаких новых inline-скриптов — CSP не меняется.
4. `assets/manifest.webmanifest:11`: `"theme_color": "#17212B"` — по master plan это surface, а не `--c-bg`; инвариант к manifest **не применять**. `background_color`/`start_url` (`:9-10`) — P2, можно оставить.
5. `NOTES.md`/ADR: зафиксировать, что light-токен добавлен, а vendor teal не мигрирован.

### 4.3. Чего НЕ делать

- **Не заменять `#0097A7` на `#17212B` по всему дереву.** В `chunks/index.bundle...css` 110 вхождений (кнопки, ripple, границы), в `index7...css` 23 (спиннер), в `index5...css` 1 (status-alert gradient), плюс SVG. Это не «meta», это палитра vendor-компонентов; замена:
  - меняет внешний вид кнопок/статусов и семантику (teal — primary, `#17212B` — surface);
  - требует cache-bust и пересборки манифеста;
  - может задеть patch-скрипты/селекторы;
  - противоречит `NOTES.md:68-71` (миграция отложена).
- **Не считать `#17212B` акцентом.** Акцент — `--c-primary:#0088cc` (`index.html:290`); `#17212B` — `--c-surface` (`:283`).
- **Не менять inline-скрипты index.html** без необходимости: CSP-хэши считаются при старте (`frontend.rs:246-280`), правка inline потребует рестарта; внешний файл — нет.

### 4.4. Проверка темы

**CI-safe `scripts/check-pnm-theme.sh` (или `.py`):**
- парсит `index.html`: `html.theme-dark { --c-bg: ... }` и `meta[name=theme-color] content`; сравнивает lowercase;
- требует наличие `html.theme-light { --c-bg: ... }`;
- проверяет, что `theme-toggle.js` содержит `getPropertyValue('--c-bg')` и не содержит жёсткой ветки `isDark ? '#0E1621' : '#0088CC'` в строке meta;
- проверяет `manifest.webmanifest` `theme_color == "#17212b"` (отдельно от DOM-инварианта);
- проверяет отсутствие `#0097A7` в `index.html`/`manifest.webmanifest` (в vendor CSS — **не** проверять).

**Browser (manual/e2e):**
```js

// meta === getComputedStyle(document.documentElement).getPropertyValue('--c-bg').trim()

// то же; ожидаем #f8f8f8
```
Нормализовать регистр: `#0E1621` vs `#0e1621`.

## 9. Приёмка T07 — конкретные доказательства

| Требование | Доказательство |
|---|---|
| deep link без токена → логин → та же сессия | `tests/e2e/deeplink_auth.js`: cold URL → authorization → login → тот же `/pnm/monitoring/sessions/<uuid>`, `.session-card`=1, tabs=5; повтор после 401 |
| `content-encoding: gzip` в `/pnm/` | curl `-H 'Accept-Encoding: gzip'` → `content-encoding: gzip`; identity → нет; HEAD/304 не сломаны; Rust-тесты |
| meta theme-color == computed `--c-bg` | e2e в dark и light: `getComputedStyle(...).getPropertyValue('--c-bg')` == meta (case-insensitive); статический чекер в CI |
| импорт сохраняет theme-toggle.js | импорт-sim 215/215, `test -f .../theme-toggle.js`, `node --check`, refs-check |
| MANIFEST 215/215 | 215 строк == 215 файлов (без `.gz`), `sha256sum -c` 215 OK, CI count gate |

**Итог:** порядок работ — deep link/импорт (риск потери URL и потери файла) → тема (инвариант) → gzip (Rust/`--locked`) → 215/215 → CI/доки. Всё, что меняет vendor CSS или backend T08/T09, — за границей T07.
