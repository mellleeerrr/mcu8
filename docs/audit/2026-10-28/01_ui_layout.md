### 1.4 Вердикты по (a)–(g)

- **(a) ПОДТВЕРЖДЕНО, причина прозрачности доказана.** `shell.rs:790-797` (каталог) и `755-762`
  (calculate) не отдают `role`; `codian-layouts.js:516-517` кладёт `entry.slots` в store без изменений;
  `setSlots` (`@980880`) не нормализует; `GridSlot.slotClass`/`slotIcon` (`@1016924`) без `role` не дают ни
  класса, ни иконки; CSS даёт фон только role-классом. Асимметрия внутри самого же файла: конструктор
  пишет `role:'AUTO'` (`codian-layouts.js:519,662,669,707,721,793…`), а ветка каталога — нет.
- **(b) ПОДТВЕРЖДЕНО по коду (не динамически).** Секция группы вешает `click`/`keydown`
  (`codian-layouts.js:455-456`), и в режиме «Конструктор» эта же секция переносится ВНУТРЬ панели
  `[data-vks-constructor]` (`1358-1361`), у которой свои `click`/`keydown` (`1329-1330`). На один клик:
  `onActivate` (489-494) + `onSectionClick`→ветка `closestItem` (1214-1218) → `select()` дважды; на Enter:
  `onKeydown` (496-502) + `onConstructorKeydown`→ветка `codianItem` (1397-1401) → тоже дважды.
  `stopPropagation` в файле нет (0 вхождений), `preventDefault` всплытие не останавливает. Вендорская
  карточка не дублирует: у неё Vue-scoped `onClick` (`@1003719`), наши узлы Vue не рендерил.
- **(c) ПОДТВЕРЖДЕНО, воспроизведено изолированно (node, /tmp/layout_race_test.js).** Копия кода
  `codian-layouts.js:143-161`: `serverCountKey = key` ставится ДО запроса (147-148), в `.then` ключ не
  сверяется (151-159). Сценарий A(13)→B(7): после ответа B `serverCount=7`, после запоздавшего A —
  `serverCount=13`, `identityName="Раскладка A"` при открытой B. `catch` сбрасывает ключ в `''` (160) —
  каждый следующий `schedule()` снова шлёт GET (ретрай-шторм вместо «навсегда failed»).
- **(d) ПОДТВЕРЖДЕНО, терминально.** `catalogState` присваивается только в `384/387/394/411/415/419`;
  входа обратно в `'idle'` нет; guard `383`, `schedule` грузит только `'idle'` (`1633`), `ensureGroup`
  при `failed` молчит (`1617`). Любая 401/404/сеть (и даже отсутствие токена на первом тике: `request()`
  → `null` → `catalogState='failed'`, 385-388) убивает группу до перезагрузки страницы.
- **(e) ПОДТВЕРЖДЕНО 54 = 52 + 2, без пропусков/дублей** (парсинг `CODIAN_SCHEMES`: 54 записи,
  `codian_01..52` непрерывно, `codian_custom_14`, `codian_custom_22`; тест `api_v3/tests.rs:2731`
  ожидает `65+54`). **Уточнение (важно):** `slot_count` ≠ хвост id у **51 из 52** базовых схем
  (`codian_02`: хвост 2, реально 4; `codian_07`: 7→13; `codian_52`: хвост 52, реально **2**). Поэтому
  инъекция `slots` из каталога обязательна: вендорский фолбэк считает N из хвоста (`ss(preset)`).
- **(f) Как безопасно отображать старые payload'ы без `role`.** Не миграцией БД, а нормализацией на
  чтении: ставить роль только слотам, у которых роль отсутствует/неизвестна; известные роли и все прочие
  поля не трогать. Развилка «пустым AUTO, занятым PEER» vs «всем AUTO» разобрана в §9 (валидация AUTO в
  занятом слоте проходит, но `setFreeUsers` перезаписывает такой слот). Точки: (1) UI — `select()` и
  нормализация драфта в `codian-layouts.js`; (2) сервер — `update_resource` и read-path (точные функции
  в §9).
- **(g) Почему нельзя массово AUTO/MEDIA.** `AUTO` в вендоре — «свободное окно автозаполнения»:
  `ManualLayoutConfigurator` (`@1041528`) по кнопке `setFreeUsers()` переводит **все** `AUTO`→`PEER`,
  раздавая свободных участников (`hasAutofillSlots`/`hasNoAutofillSlots` управляют этой кнопкой) — массовый
  `AUTO` на сохранённой раскладке означает «все окна свободны» и одну кнопку до полного перетасовывания.
  `MEDIA` вообще нет в редакторском словаре (`icons`/`titles`/`slotClass` — нет MEDIA): окно получит
  «занятый контент»-смысл в store (`["PEER","MEDIA"]` — сохраняются целиком), но без класса/иконки/подписи.
  Роли `fixed/active/rolling` определены спецификацией только для `custom_14/22` (`codian.rs`), а
  вендорский редактор знает `ROLL/ACTIVE/PEER/PRESENTATION/EMPTY/AUTO` и **не знает FIXED** — массовое
  проставление любой одной роли заведомо врёт. Правильно: `AUTO` только для пустых/безымянных окон;
  для `custom_*` — маппинг из `codian::roles()` (Default→AUTO, Active→ACTIVE, Rolling→ROLL,
  Fixed→AUTO + пометка «pinned не поддерживается редактором»).
## 2. Опровергнутое / уточнённое

1. **«Двойной setSlots от вендорского делегированного обработчика»** — опровергнуто: вендорские карточки
   палитры получают `onClick` при собственном рендере (`index6 @1003719`), делегирования на контейнер
   нет; наши DOM-узлы вендор не обрабатывает. Дубль — наш (см. (b)).
2. **«codian_52 = 52 окна, поэтому хвост совпадает»** — опровергнуто: `codian_52` = 2 окна (1+1 PiP);
   расхождение хвоста и `slot_count` есть у 51/52 схем.
3. **«`formatCalculatedSlots` теряет `role`, из-за этого окна прозрачные»** — как причина неверно:
   вендорский маппер ответа calculate (`Bee`, `index.bundle @1110741`) сам выбрасывает `role`
   (`{position,x,y,width,height,zIndex}`), calculate не пишет в стор. Прозрачность идёт из каталога/стора,
   а не из calculate. Но стрип `role` в перехвате — реальный запах дублирования (см. §4, §5).
4. **«`resources.rs:530` нормализует роль раскладки»** — нет: это роль в списке абонентов раскладки,
   к `payload.slots` отношения не имеет; сохранение роли не валидирует и не дефолтит.
5. **«`constructorCount` и `onConstructorActivate` используются»** — опровергнуто: `constructorCount`
   объявлена на `104` и больше нигде не встречается; `onConstructorActivate` определена на `1378-1383`,
   ссылок нет (grep по файлу: только определение). Оба — мёртвый код.

## 6. Тесты и критерии

1. после выбора `codian_XX` каждый слот `store.modifiedValue.slots` имеет `role` из вендорского словаря, и

5. сохранённая раскладка без `role`: после открытия пустые окна — `AUTO` с фоном `#715839`, занятые/явные

  и не дефолтится).
## 8. «Меньше кода?»

Да. Одновременно закрываются 4 дефекта и удаляется ~80 строк: дублирующие codian-ветки обработчиков
(−8), мёртвые `constructorCount`/`onConstructorActivate` (−7), перехват calculate (−~70) — при том что
серверный `/calculate` уже покрывает и `codian_*`, и `vks_*`. Нормализация ролей в одном месте (JS
`select()` + серверный `update_resource`) заменяет «правку 54 схем» и убирает необходимость хранить
роли в каталоге для 52 базовых пресетов. Единственный аргумент оставить перехват — независимость превью
от округления сервера (≤1 px) и работа на бинаре без codian-ветки; при текущем живом сервисе (маршрут есть)
выгода меньше цены дублирования.
## 9. Уточнения после ревью Lead (правило роли, точки фикса, деплой, P2)
### 9.1 Правило нормализации: AUTO в занятом слоте — валидно, но есть функциональный риск

- Валидация AUTO в занятом слоте **не отвергает**: вендорский `validateModifiedValue` (`Z`) проверяет
  только `displayName` (`chunks/index6…js` @~980990, экспорт @981409: `V.value.type==="individual" &&
  !V.value.displayName && (a.value.displayName="emptyErrorText")`); серверный
  `validate_layout_payload` (`resources.rs:1171-1181`) проверяет лишь «`slots` — массив объектов»;
  `merge_layout_slots` (`resources.rs:1201-1230`) переносит поля как есть. То есть правило Lead
  формально корректно и сохраняется.
- **Но** `setFreeUsers` (`index6 @1041423`, внутри `ManualLayoutConfigurator` @1041220) заменяет контакт
  в **любом** слоте `role==="AUTO"` свободным участником и ставит `role:"PEER"`
  (`if (t.role!=="AUTO" || !e.length) return t; … role:"PEER"`). Значит `AUTO` на занятом слоте — это
  дыра автозаполнения: одно нажатие «Заполнить свободные окна» перезапишет занятое окно чужим контактом.
- Рекомендация: `AUTO` — пустым слотам (нет `abonent_id`/`contact_id`/`display_name`), `PEER` — занятым
  (`normalizeRoles`: `role = occupied ? 'PEER' : 'AUTO'`, 3 строки). Плюс визуально точнее: занятое окно
  получает `--peer #5c5c5c`, а не `--autofill #715839`. Если Lead оставляет единое `AUTO` — фиксирую как
  принятый риск (прозрачность лечится в любом случае; участник в окне рендерится независимо от роли —
  `GridSlot.realTimeContact`/`contact`).
### 9.2 Три точки фикса (основная / JS / read-path)

### 9.3 Деплой: фикс переживает импорт

- Вендорский UI отдаётся с диска через `tower_http::ServeDir` (`crates/vks-server/src/frontend.rs:83-87`),
  без встраивания в бинарь: live `/mcu/codian-layouts.js` = 82740 B == размер файла на диске. Значит
  JS/HTML-правки доезжают без `cargo build` (Rust-правки требуют пересборки — в этой задаче запрещена).
- `scripts/import-pnm-frontend.sh`: сохраняет проектный слой (`130-140`: perf-overrides.js, api-errors.js,
  codian-layouts.js) и возвращает его вместе с блоком `prostor:project-layer` в `index.html` (`224-240`);
  `MANIFEST.sha256` пересчитывается по факту **после** восстановления (`289`:
  `find . -type f … | xargs sha256sum > MANIFEST`) → хеш новой версии codian-layouts.js попадёт в манифест
  автоматически, ручной пересчёт не нужен; повторный `--force` ре-импорт фикс не откатывает.
- Кэш клиента: не-хэшированные файлы отдаются с обязательной ревалидацией (`frontend.rs:45`), т.е. после
  деплоя достаточно обновить страницу.
### 9.4 P2: удаление дублирующих веток безопасно

Удаление `codian-layouts.js:1214-1218` (`onSectionClick` → `closestItem`) и `1397-1401`
(`onConstructorKeydown` → `codianItem`) не ломает ни мышь, ни клавиатуру:
1. карточки Codian всегда лежат внутри секции группы (`1310-1312` — manual, `1358-1361` — конструктор),
   а у секции свои `click`/`keydown` (`455-456`);
2. `keydown` от сфокусированной карточки всплывает к секции → `onKeydown` (`496-502`) остаётся
   единственным обработчиком Enter/Space для Codian-карточек;
3. ветка карточек конструктора (`1208-1213`) и Enter в поле счётчика (`1386-1389`) не затрагиваются;
4. вендорских обработчиков на наших узлах нет (`LayoutPresetSelector` @1003719 — Vue-scoped `onClick`).
Тест: клик и Enter по `[data-codian-id]` → ровно один `setSlots` (обёртка-счётчик в playwright) и один
изменённый `preset`.
