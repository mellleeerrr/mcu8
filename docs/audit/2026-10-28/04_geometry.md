## 1. Подтверждённые числа

### 1.1. Пересечения и выходы за границы: НОЛЬ

Матрица: 6 режимов × N=1..100 × холсты {1280×720, 1920×1080, 1921×1081, 1921×1080, 1279×719, 1919×1079,
1366×768} × опции {0, g8, g12, m24, m64, g12m24}. Проверялись попарные пересечения с положительной площадью,
выход за `[0,W]×[0,H]`, число слотов == N.

**Результат: 0 пересечений, 0 выходов, всегда ровно N слотов** — обе реализации, все режимы и размеры. Ширины —
разности соседних округлённых рёбер (`w = x2 − x1 − gap`), поэтому соседи стыкуются ровно в `gap`. Исключение —
вырожденный холст: `gallery(100, 10×10)` даёт **50 слотов вне канваса** из-за `max(1.0)`; при ≥320 px нет.

### 1.2. `vks_grid_43`: клиент 7×7 против Rust 9×5

| Реализация | rows×cols | cost | заполнение | плитка |
|---|---|---|---|---|
| `grids.rs::gallery` (конструктор, сервер) | **5×9** | **119.012** | **95.56 %** | 142×144 (квадрат) |
| JS `buildSymmetricLayout('grid')` | **7×7** | 120.000 | 87.73 % | 182×103 (16:9) |
| `grid.rs::best_rows_cols` (авто-сетка MCU) | **7×7** | — | — | 274×154 (1920) |

Разрыв — 0.988 балла (0.8 %). Разложение: `rows=5: 79.01 + 2·20 = 119.01`; `rows=7: 0 + 6·20 = 120.00`. Выбор
переворачивается при штрафе за пустую ячейку ≥20.99 (сейчас `20.0`, `grids.rs:280`) — хрупкая константа.

**Консенсус — 7×7: три реализации из четырёх.** `grid.rs:14-40` → 7×7; `preset.rs::balanced_grid` (порт вендорской
логики `preset_equal_*`) → **7×7**; JS → 7×7. Выброс — только `gallery_cost`. **Один алгоритм с явной константой
политики:** оставить `gallery_cost`, вынести штраф в `const WASTE_WEIGHT = 0.0` (`grids.rs:280`). Проверено: при
`waste=0` выбор совпадает с клиентом/`balanced_grid` для **всех N=2..100 (0 расхождений)**, golden не меняется
(**0 из 174** кейсов) → тесты зелёные, «два ответа в одном крейте» исчезают. Это готовое P1-решение.

### 1.4. «Окно 1921 px»: воспроизводится, но в `grid.rs`, а не в `vks_grid_5`

`grids.rs::gallery` на 1921×1081 для N=5 даёт max width **641 px** (ширина == канвас только при N=1 — легитимный
полный экран). Полнокадровое окно даёт **`grid.rs::grid_rects:78-84`**: последний тайл ряда берёт `w − x_cursor`,
поэтому при одном тайле в последнем ряду (N ≡ 1 mod cols) ширина = весь канвас: **N = 3, 7, 13, 21, 31, 43, 57,
73, 91**; N=43 → **1920×156** (на 1921×1081 → 1921×156), аспект 12.3:1. Покрытие/пересечения не нарушены.

**Доступность в проде подтверждена:** `CANVAS_SIZE = (1920,1080)` (`compositor.rs:20`); `layout_from_descriptor`
уходит в `GridLayout::compute` при пустом `desc.geometry` (`engine.rs:243-283`); `seat_video_or_expand` →
`regrid_for_video` (`engine.rs:165-190, 712-741`) перезаписывает geometry через `GridLayout::compute`; полный
`scaled_slot_rects` (`engine.rs:199-224`) переносит обе границы в холст комнаты half-up, сохраняя полноширинность.
Комната в auto-режиме с 3/7/13/… участниками получит полноширинное окно — баг отображения при целых инвариантах.

### 1.5. Клиент перехватывает `calculate` → превью ≠ сервер

`codian-layouts.js:1722-1736` (fetch) и `1768-1783` (XHR) подменяют ответ `POST /video_layouts/calculate` для любых
`vks_*`/`codian_*` функцией `formatCalculatedSlots` (`:1648-1699`): 1280×720 и масштаб `round(coord × reqW/1280)`.
Серверный ответ для этих id не используется вообще.

| Режим | max клиент↔сервер | слотов с Δ≥0.5 px |
|---|---|---|
| `grid` @1920×1080 | **1745 px** (N=65: `(0,810,213,135)` vs `(1745,720,175,180)`) | 3616/5050 |
| `grid` @1280×720 | 1164 px (N=65) | 2562/5050 |
| `dual`/`pin_*` @1920×1080 | 2 px | 2136…2741/5050 |
| `dual`/`pin_*` @1280×720 | **0 px** | 0/5050 |

Для **любого id с опциями** (`vks_grid_g12_m24_9`, `vks_pin_l_g8_7`) `formatCalculatedSlots` возвращает **пустой
массив**: регулярка даёт arch=`grid_g12_m24`, которого нет в `buildSymmetricLayout` → `[]` (проверено реальным JS в
node: `[]`, `[]`); сервер такие id поддерживает.

**Уточнение о природе расхождения.** Это НЕ «MCU зашит на 1920»: MCU считает в пространстве 1920×1080, затем
`scaled_slot_rects` масштабирует в холст комнаты; игнор x/y для explicit-пресетов — контракт (`gateways.rs:1895-1902`,
«иначе смешение единиц 1280/1920»). Причина 1745 px — **разные rows/cols**, а не игнор размера. Область: 1745 px —
только `vks_grid_*`; pin/dual ≤2 px (при масштабе ≠1); **Codian ≤1.0 px** (каталог×scale с `round` против `floor(coord·W/den)`;
65/2028 координат). Запрос вендора — `{preset, width, height}` (маппер `Uee` в `chunks/index.bundle-2.2.1.66.js`),
сервер принимает те же ключи (`shell.rs:733-740`).

## 4. Минимальная формула, патчи, места правок

Обе границы окна уже вычисляются в `get_grid_edges`; дублируется только вывод ширины. Минимальная форма — одна
функция на ось:

```
spans(start, count, cell, gap):  step = cell + gap;  e[i] = round(start + i*step), i = 0..count
span_i = (e[i], e[i+1]);  width = x1 - x0 - gap   # gap вычитается ровно один раз
```

Сейчас `(col_edges[c+1] − col_edges[c] − gap).max(1.0)` продублировано **43 раза** в `grids.rs` и **41 раз** в JS;
плюс ~4–5 копий блоков «нижних сквозных рядов» (`grids.rs:368-387, 416-435, 467-486, 603-622`; JS `:756-774,
816-833, 864-881, 913-930`). Сведение к `spans()` + один цикл по (r,c) убирает ~120 строк Rust и ~200 строк JS без
изменения пикселей. Правки: `grids.rs:234-238` и 17 мест вывода `w/h`; `codian-layouts.js:646-652, 790-980`;
`+gap` в `get_grid_edges` (`grids.rs:236`, JS `:649`) убрать — он компенсируется вычитанием (трюк округления).

**Три минимальных патча (по цене/эффекту):**

1. `grids.rs:280` — `… * 20.0` → именованная `const WASTE_WEIGHT: f64 = 0.0;`. Эффект: Rust-конструктор == клиент
   по rows/cols для всех N=2..100 (0 расхождений), golden зелёный без правок (0/174 кейсов меняют сетку). P1.
2. `grid.rs:78-84` — не отдавать последнему тайлу весь остаток: ширины `base_w`, ряд центрировать, высота
   последнего ряда `base_h` → исчезает окно 1920/1921 px при N ≡ 1 (mod cols). Цена: инвариант «покрывают canvas
   целиком» (`lib.rs:23`, `rect.rs:8-10`, `grid.rs:42-47`) → «без пересечений и выходов, неполный ряд центрирован,
   незанятая площадь — фон». Тесты: `grid.rs:108-118` (`total_area == area`), `:139`, `:174`, `:210-225` + кейс
   N=13/43. Альтернатива без смены инварианта: при `N mod cols == 1 && rows > 1` брать `cols−1` (13 → 5×3), но
   аспект хуже (384×360 против 480×270).
3. Удалить клиентский перехват `calculate`: `formatCalculatedSlots` (`:1648-1699`, 52 строки) + два перехватчика
   (`:1722-1738`, `:1768-1785`, ~35) = **≈87 строк JS**. Проверки: (a) сервер принимает те же `preset/width/height`
   (`shell.rs:733-740`), маппер `Bee` читает те же `x/y/width/height/z_index`; (b) перехват только для `vks_`/
   `codian_` (`:1725-1727`) → dynamic/auto/manual (`preset_*`) и раньше шли на сервер, не ломаем; (c) `computeSlots`
   (`:985-987`) и `buildSymmetricLayout` (`:654-983`, 330 строк) **остаются**: иконки (`:1269`) и черновик
   (`:1413`) — «−330 строк» неверно. Изменение поведения одно: id с N>100 получают обрезанную до 100 геометрию,
   а сервер вернёт 400 (`grids::parse` фильтрует 1..=100) — исправление, объявить отдельно.

## 5. Почему НЕ надо удалять авто-сетку (`grid.rs`) как «дубль»

1. **Другой контракт:** `Vec<rect::Rect>` (`u32`) для композитора MCU (`engine.rs:281, 718`) против `Vec<SlotRect>`
   (`f64`) для конструктора.
2. **Другие инварианты, зафиксированные тестами:** `grid.rs` гарантирует точное покрытие (`total_area ==
   canvas.area()`, `:139, 174`); `gallery` при `g`/`m` обязана оставлять зазоры и поля (`tests/grids.rs:161-183`).
3. **Разные входы:** `grid.rs` — по числу участников комнаты без id пресета; `grids.rs` — по id с разбором `g`/`m`.
4. **Алгоритм выбора сетки не идентичен:** 36/100 N дают разные ответы — «удаление дубля» молча изменит картинку
   в 36 случаях из 100.
5. Максимум: вынести **только** выбор (rows, cols) в общий helper с параметром-cost (≈−30 строк), оставив два
   рендерера.

## 6. Лишний/опасный код

* `.max(1.0)` / `Math.max(1, …)` — 43 + 41 сайт: на реальных холстах мёртвая страховка, на вырожденных — источник
  выхода за канвас. Достаточно `max(0.0)` + одна проверка размера.
* `+gap` в `get_grid_edges`, требующий компенсирующего `-gap` в 17 местах; `formatCalculatedSlots` (52 строки) —
  дубль серверной арифметики, дающий `[]` для id с опциями; 4 копии блока «нижний сквозной ряд» в Rust и 4 в JS.

## 7. Тесты: что реально ловят

`tests/grids_geometry_golden.rs` + `tests/fixtures/grids_geometry_1280x720.json`: **174 кейса** = 29 базовых схем ×
6 наборов опций (`0, g8, g12, m24, m64, g12m24`); базовые — `vks_grid_{1..9,13,16,25,100}` +
`vks_pin_{l,r,t,b}_{2,5,9,25}`. Проверки: набор id, непустые слоты, `z_order==0`, внутри канваса ±0.5 px; **точное**
совпадение пикселей (≤1e-6); масштаб 1920×1080 с допуском **±2 px**. Фикстура сгенерирована самой реализацией
(`regenerate_golden`) — self-snapshot, не оракул (честно написано в шапке).

Ловит сдвиг любой границы ≥1e-6 px и порядок окон в 174 id. **Не ловит:** расхождение Rust↔JS (клиент не
вызывается), `N=43` и вообще 10..12,14,15,17..24,26..99, `dual` (0 кейсов), нечётные холсты, `grid.rs` (окно
1921×156 не замечается), `role`/PiP Codian (отдельный `codian_geometry_golden.rs`). `tests/grids.rs` (219 строк)
сильнее: N окон, внутри, пересечения ≤0.5 px, 16:9, точные пиксели `g8`, margin/gap, потолок опций — но и он не
проверяет полноширинное окно в `grid.rs`. Для патча №1: при `WASTE_WEIGHT=0.0` ни один golden-кейс не меняет сетку,
править golden не нужно; но согласие клиента с сервером не проверяет ни один тест. Новые тесты: parity-эталон «id →
слоты» для JS (node в CI), кейсы N=43/65/91 в golden, `grid.rs` N ≡ 1 (mod cols).
