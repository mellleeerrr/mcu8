# ADR-0034. Нативный H.323: поэтапный стек, pycrate-сайдкар на T16

Статус: accepted (2026-10-29, T16)
Связано: ADR-0007 (H323Plus FFI, superseded), `docs/audit/2026-10-29/02_h323_p6.md`
§7/§12, `docs/audit/2026-10-29/00_MASTER_PLAN.md` T16

## Контекст

T16 требовал «нативный Rust H.323: убрать Python sidecar + ffi.rs, сохранить
полную матрицу кодеков, fastStart, reverse OLC, H.239, H.235 SRTP». Проверка
текущего состояния показала:

- `src/ffi.rs` и H323Plus/OPAL FFI уже удалены в T03c (`aef9257`); в
  `vks-gateway-h323` нет pyo3, libloading, C++-линковки и `unsafe`-границы.
  Удалять в T16 нечего.
- Работающая сигнализация — Python/pycrate 0.8.1 сайдкар (`uac.rs`/`uas.rs`,
  JSON IPC) плюс нативный TPKT/Q.931-каркас (`q931.rs`). Это единственный
  стек, который реально проводит вызовы с Polycom-терминалом.
- Аудит §7/§12 оценивает нативный ASN.1-стек в 3,5–6,4 тыс. LOC и 13–24 дня
  (PER-кодек, H.225/H.245, H.239, H.235, тесты), причём `rasn 0.29` UPER
  содержит `todo!()` для BMPString/TeletexString, а `h245.asn:3094`
  (`sessionDescription`) использует BMPString. Это не «доделать за волну».
- FastStart, reverse OLC и H.239 в сайдкаре **отсутствуют**; «сохранить»
  их нельзя — можно только честно не объявлять и запланировать.
- H.235/H.245-шифрование не реализовано. Молчаливый plaintext-fallback при
  запросе TLS/токенов — уязвимость, а не совместимость.

## Решение

1. **Не удалять сайдкар в T16.** Нативный ASN.1-стек внедряется поэтапно по
   S0–S9 из аудита; удаление Python-процесса — только после паритета и
   golden-подтверждения, а не до него. ADR-0007 (FFI) считается замещённым:
   FFI-путь уже физически удалён, возвращать его нельзя.
2. **Нативный слой расширяется только там, где он безопасен без ASN.1:**
   строгий TPKT/Q.931-каркас, IP+SSRC-латч RTP, lifecycle/счётчики. H.225/H.245
   остаются за pycrate до соответствующей стадии S-плана.
3. **H.235 fail-closed.** Setup/Connect с `h245SecurityCapability` без
   `noSecurity`, с `h245SecurityMode` ≠ `noSecurity`, с `tokens`/`cryptoTokens`
   или OLC с `encryptionSync` отклоняется с `securityDenied`; plaintext не
   подставляется. Это сохраняется и после перехода на нативный стек.
4. **UII — один IA5-символ.** DTMF из комнаты уходит как H.245
   `UserInputIndication.signal` (`0-9*#ABCD`), а не как hex-код RFC 4733;
   входящий UII (signal/alphanumeric) уже декодируется в те же события.
5. **Честный `active_calls`.** Статус H.323 считает и mock-реестр
   `H323Gateway`, и реальные сессии `GatewayCallRegistry`
   (`active_h323`/`inbound_h323`, только живые). UI больше не показывает 0
   при подключённом терминале.
6. **Golden-каркас.** `tests/golden/h323/` хранит независимые Polycom-кадры и
   детерминированные H.235-векторы; `tests/golden_h323.rs` проверяет нативный
   каркас, отсутствие паник на усечении/мутации, `python/test_golden_vectors.py`
   — паритет pycrate и fail-closed. SHA256 зафиксированы.
7. **Развёртывание** остаётся с pinned Python 3 + pycrate 0.8.1
   (`VKS_H323_PYTHON`, `VKS_H323_HELPER`, `VKS_H323_UAS_*`); это явная
   runtime-зависимость, а не скрытая FFI-библиотека.

## Последствия

- Эпик нативного переписывания **не закрыт** T16; он остаётся P2 с
  измеримыми стадиями S0–S9 и критерием удаления сайдкара «паритет + golden».
- FastStart, reverse OLC и H.239 по-прежнему не поддерживаются и не
  рекламируются; в README и golden README это сказано прямо.
- H.235/SRTP не реализован: поддерживается только cleartext, а
  зашифрованные вызовы отклоняются. Это осознанный fail-closed, не «частичная
  поддержка».
- Появляется runtime-зависимость от Python и pycrate; она документирована и
  проверяется тестами, но увеличивает поверхность поставки.
- `rasn`-путь нельзя считать готовым без обхода/патча BMPString/TeletexString;
  это первый технический риск стадии S3.

## Отклонённые альтернативы

- **Удалить сайдкар сейчас.** Потеря единственного рабочего H.323-стека,
  регресс для живых терминалов, нарушение критерия аудита «сначала паритет».
- **Вернуть H323Plus FFI.** Уже удалён, тянет C++/лицензии/падения процесса;
  ADR-0007 замещён.
- **Объявить fastStart/reverse OLC/H.239/H.235 реализованными.** Нет кода и
  golden-доказательств; это был бы фиктивный паритет.
