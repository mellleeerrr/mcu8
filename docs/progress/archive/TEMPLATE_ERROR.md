# Шаблон записи ошибки в PROGRESS.md

> Использовать при заполнении секции «Ошибки, с которыми столкнулись» в PROGRESS.md.

## Формат записи

| Поле | Содержимое | Пример |
|---|---|---|
| **Ошибка** | Краткое (1 строка) описание. | `str0m: DTLS handshake timeout при 1-to-1 forwarding` |
| **Где/когда** | Крейт, файл, строка, фаза, дата. | `vks-media-sfu/forwarder.rs:142, фаза 2, 2026-10-20` |
| **Симптом** | Что видно снаружи: лог, поведение, тест. | `Тест test_forward_1to1 падает с 'DTLS handshake timeout after 5000ms'` |
| **Причина** | Корневая причина (root cause), не симптом. | `str0m 0.16 требует явной установки DTLS-сертификата через DtlsCert, в 0.15 это делалось автоматически` |
| **Как исправили** | Конкретное изменение: коммит, diff, новая версия. | `Добавил DtlsCert::new(...) в bootstrap.rs (коммит abc123). Обновлено в PROGRESS.md.` |
| **Профилактика** | Что сделано, чтобы ошибка не повторилась (тест, правило, ADR). | `Добавлен e2e-тест dtls_handshake.rs. Правило 2.1 усилено: проверять CHANGELOG при обновлении str0m.` |
| **Статус** | open / fixed / accepted / wontfix | `fixed` |
| **Связанные** | ADR, issue, другие ошибки. | `ADR-0004, ADR-0012` |

## Правила заполнения

1. **Не удалять** записи об ошибках, даже исправленные — переносить в архив.
2. **Причина ≠ Симптом.** Симптом — что видно. Причина — почему. Разные вещи.
3. **Профилактика обязательна** для ошибок, встречающихся > 1 раза.
4. Если ошибка не исправлена и принят «как есть» (accepted) — обязательно ADR с обоснованием.
5. Одна и та же ошибка (та же причина, тот же крейт) не должна встречаться во второй раз без ссылки на первую.
