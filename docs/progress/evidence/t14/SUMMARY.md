# T14 — аватар участника убран из плитки раскладки, подпись ×2 сохранена

Дата: 2026-10-22. Прод: `client/pnm-frontend/deployed/pnm/index.html` (блок `<style id="prostor-pnm-overrides">`).
Харнесс: `tests/e2e/label-zoom.js`. Артефакты: `docs/progress/evidence/e2e-label-zoom/`.

## Задача (дословно)

> «нужно вычистить именно этого аватара чтобы он не отображался в раскладке
> `<div class="tc-avatar-container layout-grid-slot__avatar" id="tc-avatar-8ab7cc0d-…">…</div>`
> чтобы он отображался у нас в 2 раза больше но вчитывай все расскладки которые есть
> 1, 2, 3, 4, 5 +, 8, 9, 10 +, 25, 34 + все варианты чтобы они везде выглядели четко
> чтобы они не выпирали с большим количеством пользователей»

## Как принималось решение

Четыре агента работали параллельно, каждый — с мандатом **отстаивать свою позицию**
до реального согласия или реальной победы, и обязательным steel-man контраргументом против себя:

| Агент | Роль | Итог |
|---|---|---|
| `intent-critic` | адвокат диабазы: трактовка задачи | подтвердил трактовку **(A)** «убрать аватар, имя ×2 оставить»; опроверг (C) «аватар ×2» замерами (перекрытие подписи на 2.6px и бейджа в 34+) |
| `avatar-scout` | ультра-разбор зависимостей аватара | вывел формулу сдвига и инвентарь зависимостей (file:line), отбросил 5 способов скрытия замерами |
| `regression-audit` | регрессионный аудит | см. §«Раунд контраргументации» |
| `pw-harness` (pw-plan) | честность Playwright-проверок | переделал ложно-зелёную проверку аватара, добавил чувствительность к откату |
| саб-агент lead-уровня | независимая адверсarial-проверка | вывел формулу с нуля, подтвердил рецепт, нашёл латентный баг превью-плитки |
| саб-агент lead-уровня | регресс-скан остальных экранов PNM | см. §«Раунд контраргументации» |

Ограничение рантайма: саб-агенты уровня тиммейта не запускаются (`delegation depth 1 of 1`),
поэтому их подзадачи они выполняли самостоятельно; саб-агенты запускались lead-ом.

## Что было

* Аватар в плитке — круглая градиентная плашка 2em×2em с иконкой человека
  (`.tc-avatar-container.layout-grid-slot__avatar`), вендорский `TcAvatar`.
* Подпись под ним — `.layout-grid-slot-dn__text`, уже ×2 (T13, `2863dc0`).
* Сдвиг центровки подписи был `-2.335em` (T12b) — он рассчитан **на наличие аватара**:
  `header/2 + (avatar + gap)/2` = `1em + (2em + .67em)/2`.
* Латентный дефект: вендор рисует иконку человека фиксированными 24px
  (`.tc-avatar-container .tc-avatar__name-icon{font-size:24px}`, `svg{height:24px;width:24px}`),
  а бокс аватара = 2em = **16px** в 9+/25/34+ → глиф вылезал за плашку на 4px в каждую сторону.
* Латентный баг: константа `-2.335em` промахивалась в плитке с превью кадра
  (вендор рисует `MediaPreview` 24×24 px вместо аватара 2em) на +4.00px (шрифт 8px) / +1.99px (шрифт 10px).

## Что сделано

```css
/* T14 */
.layout-grid-slot .layout-grid-slot__avatar { display: none; }
.layout-grid-slot-content:has(.layout-grid-slot-dn) { transform: translateY(-1em); }
.layout-grid-slot-content:has(.layout-grid-slot-dn):has(> .media-preview) {
  transform: translateY(calc(-1em - 12px - 0.335em));
}
```

* **Селектор — класс, а не id**: `id` вида `tc-avatar-<uuid>` генерируется заново на каждый маунт
  (`TcAvatar.created → getUUID`) — правило по id было бы одноразовым no-op.
* **Строго scoped**: `.layout-grid-slot__avatar` встречается ровно в двух чанках
  (`index6`, `index-legacy6`) и только на корне `TcAvatar` плитки. Остальные аватары UI
  (`.grid-slot-contact-item__avatar`, `.layout-table-item-receiver__avatar`, `.header-profile__avatar`,
  `.user-list-item__avatar`, `.monitoring-address-book__group-avatar`) имеют другие BEM-префиксы и не задеты.
* **Специфичность 0,2,0** (выше вендорской): CSS чанка 7 (layout-grid) подключается Vite рантаймом
  **после** инлайн-блока, поэтому правило равной специфичности проигрывало бы по порядку в документе
  (это уже ловило нас в T13). `display` вендор для этого класса не задаёт → `!important` не нужен.
* **Сдвиг пересчитан**: без аватара `display:none` убирает элемент из flex-потока, и `gap .67em`
  между единственным оставшимся элементом **не применяется** ⇒ сдвиг = `header/2` = ровно `1em`.
  Сдвиг и скрытие — **парные правила**: менять одно без другого ломает вёрстку.
* **Страховка превью** `:has(> .media-preview)` — триггерится на *наличии превью* (а не на «нет аватара»),
  поэтому не сломается, если аватар исчезнет из DOM или вендер переименует класс; заодно чинит
  латентный баг превью-плитки. Специфичность 0,3,0 > 0,2,0.
* Пересобрана строка `index.html` в `client/pnm-frontend/MANIFEST.sha256` (`sha256sum -c` — OK, 212/212).

## Раунд контраргументации (что реально изменило решение)

1. **«Просто добавить `display:none`» — отвергнуто замерами.** С константой `-2.335em` подпись уезжает
   вверх на 1.335em: `dy = −16.03px` (шрифт 12px) и `−10.69px` (шрифт 8px) на **всех** 10 размерах.
   Вывод: сдвиг и скрытие нельзя разделять.
2. **Способы скрытия отброшены измерением, а не рассуждением**: `visibility:hidden` и `opacity:0` оставляют
   дыру 2em (подпись визуально ниже центра, элемент ещё и hit-testable); `position:absolute` уходит из
   потока, но **остаётся нарисованным**; `display:none` на внутреннем `.tc-avatar` оставляет контейнер 2em;
   удаление из DOM требует правки вендорного чанка 6 (запрещено правилами проекта).
3. **Селектор страховки уточнён по итогам спора**: `:not(:has(.layout-grid-slot__avatar))` (прокси)
   заменён на `:has(> .media-preview)` (факт) — снимает хрупкость «условие ≠ признак».
4. **Сохранена защита от «ложно-зелёного» харнесса**: старая проверка `size N: avatar rendered`
   меряла `Boolean(querySelector)` и проходила при `display:none`. Заменена на «аватар **не виден**»
   (display/visibility/opacity + нулевая площадь + hit-тест + проверка крашеных потомков).
5. **Сильнейший контраргумент против правки** (steel-man): «аватар — носитель идентичности и цветовой
   якорь (градиент = хеш имени), а `-1em` — вторая магия рядом с `-2.335em`».
   **Ответ**: связей стало *меньше* (было header + avatar + gap, стало header) — константа стала
   менее хрупкой; потеря цветового якоря касается только админского превью-редактора
   (`.layout-grid-slot*` не используется в боевой сетке конференции), а аватары остаются
   в списке «Получатели», в панели видеослота, в карточке комнаты и в шапке.

### Что добавлено в харнесс по итогам спора

* `size N: tile avatar takes no space in the flow` — аватар должен быть **вне потока** (бокс 0×0),
  иначе `visibility:hidden` / `opacity:0` / скрытие внутреннего `.tc-avatar` прошли бы как «скрыто»,
  оставив дыру 2em.
* `preview tile: the preview guard shifts the preview tile separately` — негативный тест: сдвиг
  превью-плитки обязан отличаться от сдвига обычной на `12px + .335em` (замерено: −8px против
  −22.68px при шрифте 8px), иначе страховка умерла бы молча.
* `size N: label does not overflow vertically` + `size N: horizontal clipping uses the vendor ellipsis`.
  Первая версия этой проверки требовала `!overflowX` — **по замеру отозвана** (обрезка длинного имени
  штатна: вендор даёт `nowrap + overflow:hidden + text-overflow:ellipsis`, `scrollW=566` при `clientW=171`,
  за плитку ничего не вылезает). Корректный критерий — контейнерность, а не отсутствие обрезки.
* `CANDIDATE_CSS` синхронизирован с продом (`:has(> .media-preview)`).

## Область действия (важно для заказчика)

`.layout-grid-slot` встречается **только** в чанках `index6` / `index-legacy6` — это **редактор
раскладки в админке** (`/monitoring/{conferences,sessions}/:id/layouts` → вкладка «Ручная настройка»).
Живая вкладка «Видео» мониторинга рисует `<video class="auto-layout-configurator-content__video">`
(статичный webm), а не сетку слотов; в `index3`/`index9`/`index10` вхождений нет.
Если под «плиткой раскладки» имелась в виду плитка **в самой конференции** (клиент участника) —
это другое место, и в этом репозитории такого клиента нет (`client/vks-client-sdk` — только
сигналинг и рендер видео). Вендорский переключатель `slot_avatars` (HIDE/SHOW/DEFAULT) как
альтернатива недоступен: UI есть (`data-qa="slot-avatars-select"`), но сервер поле не реализует
(в `crates/**/*.rs` — 0 совпадений), то есть CSS — единственный рабочий рычаг.

## Ограничения (осознанные)

* CSS **скрывает** элемент, но не удаляет его из DOM (`id` в инспекторе останется) — удаление требует
  правки вендорного чанка 6, что запрещено правилами проекта и ломается при обновлении фронта.
* Подпись в 25/34+ — 126px при ширине полосы 141px; длинные имена уходят в вендорский `ellipsis`
  (проверено: обрезки нет, многоточие есть).
* Плитка с превью проверена симуляцией DOM (`MediaPreview` 24×24): CSS-арифметика и геометрия
  подтверждены, но реальный data-path (контакт с превью) не прогонялся — в комнате `contacts.file = 0`.
* `:has()` не поддерживается в legacy-браузерах — это долг T12b, аватар его не ухудшает.
* При обновлении вендорского фронта (`scripts/import-pnm-frontend.sh`) оверрайд надо перепроверить:
  при переименовании `.layout-grid-slot__avatar` или `.media-preview` правила перестанут матчиться.
