[27] 2. Архитектура и управление раскладками Codian MCU 4200 Series
[28] В архитектуре видеосерверов Codian MCU 4200 Series (Cisco TelePresence MCU) подсистема микширования видеопотоков (Continuous Presence) формирует индивидуальную раскладку для каждого подключенного терминала. Руководство Codian MCU 4200 предусматривает два метода выбора структуры экрана и многоуровневую систему приоритетов.
[29] 2.1. Семейства раскладок (Layout Families) и Фиксированные макеты (Available Layouts)
[30]<ListBullet> Пять предустановленных семейств (Family 1 – Family 5): динамические наборы правил, в которых MCU автоматически переключает геометрию сетки при изменении числа участников в конференции. Например, при выборе Family 4 (симметричная матрица равных окон) для 4 участников формируется сетка 2×2 (4 окна). При подключении 5-го видеоучастника MCU автоматически переключает раскладку на 3×3 (9 окон), а при дальнейшем росте — на 4×4 (16 окон).
[31]<ListBullet> Исключение собственного потока при расчете размера сетки: при подсчете числа участников для автоматического выбора макета внутри семейства MCU не учитывает собственный видеопоток (Self-view) смотрящего абонента, чтобы не дробить экран на более мелкие ячейки без необходимости.
[32]<ListBullet> Палитра из 52 фиксированных раскладок (Available layouts): статические по своей геометрии шаблоны, выбираемые вручную на вкладке Custom Layout. В отличие от семейств, фиксированный макет сохраняет заданное количество и расположение окон независимо от того, сколько участников вошло или вышло.
[33] 2.2. Логика распределения участников по окнам (Voice Activation & Priority)
[34]<ListBullet> Голосовая активация (Voice-controlled layout — по умолчанию): в раскладках с выделенным крупным окном (или несколькими крупными окнами) участник, говорящий громче всех (Active speaker), автоматически выводится в самое большое окно.
[35]<ListBullet> Низший приоритет самопросмотра (Self-view lowest priority): собственное изображение участника имеет самый низкий приоритет при заполнении ячеек. Пока все остальные абоненты видят текущего говорящего в главном крупном окне, сам говорящий в своем крупном окне видит предыдущего спикера.
[36]<ListBullet> Статус «Важный участник» (Important): в любой момент времени администратор может назначить одного участника конференции «Важным» (Important). В режиме голосовой активации этот участник принудительно закрепляется в самом крупном окне раскладки независимо от того, кто говорит громче всех (полный функциональный аналог окна Fixed / Static user).
[37]<ListBullet> Заполнение малых ячеек: остальные окна заполняются участниками в порядке убывания их недавней речевой активности.
[38] 2.3. Настройка раскладок в веб-интерфейсе MCU
[39]<ListBullet> На уровне всей конференции (Conferences → [Имя конференции] → Custom Layout): клик по любой из 52 иконок в палитре Available layouts автоматически переводит статус Current status из Disabled в Enabled. Кнопка «Make new participants see this view» назначает выбранный макет всем новым подключающимся абонентам, а кнопка «Switch all participants to this view» мгновенно переключает на него всех текущих участников.
[40]<ListBullet> Глобальные команды во вкладке Participants (секция All participants): позволяют одной кнопкой вернуть всех участников в режим голосовой активации («Force all participants' view layouts to voice-activated mode»), переключить всех на полноэкранный вид 1×1 («Select a full screen layout for all users») или заблокировать управление раскладками с удаленных пультов («Disable all users from being able to control their layout with the far end controls»).
[41]<ListBullet> На уровне отдельного участника (Participants → [Участник] → Display / Custom layout): позволяет выбрать индивидуальное семейство (Family 1–5) или назначить персональный фиксированный макет из 52 доступных (Participant custom layout) только для конкретного терминала.
[42] 2.4. Удаленное управление с пульта терминала (FECC / DTMF)
[43]<ListBullet> ВВЕРХ (UP) / ВНИЗ (DOWN) или клавиши 2 / 8 (DTMF): циклическое переключение между доступными семействами раскладок, а также пользовательскими макетами Conference custom layout и Participant custom layout.
[44]<ListBullet> ВЛЕВО (LEFT) / ВПРАВО (RIGHT) или клавиши 4 / 6 (DTMF): принудительный ручной выбор конкретного участника для отображения в самом крупном окне (отключение автоматической смены по голосу).
[45]<ListBullet> ЗУМ (ZOOM +): переход в режим сквозного управления поворотной камерой (FECC tunneling) того участника, который в данный момент отображается в главном окне.
