## Метод и его границы

* **Структура** (число окон, состав, явные дроби вида 2/3, 4/9, 5/6) берётся из
  **спецификации** — это истина.
* **Чертежи вендора** используются как **независимая проверка топологии**
  (число окон + карта крупных окон) и как источник пропорций, **когда спека
  молчит**. Это **оракул теста**, а не производственные данные: в
  `crates/vks-layout/src/codian.rs` попадают **рациональные** пропорции.
* **Чертёж схематичен.** Пример: для макета №5 спецификация говорит «4/9 экрана»,
  а чертёж показывает крупное окно высотой 2/5. Точных пикселей нет ни у одного
  источника — есть структура, и её берём из спецификации.
* **«Дрожащие» пропорции** 43/46/49 — **историческое измерение**, а не production.
  В R4 принято: №43 — равная матрица 4×5 (`320×144`), №46 — симметричный центр
  4×4 (малые `320×180`, крупные `480×360`), №49 — верх `2/5 = 0.4` (сетка 4×5,
  `640×288` + 3 ряда по `320×144`). Причины, числа и цена компромисса —
  `SUPERSEDED.md`; для 43/46 есть независимый fixture
  `crates/vks-layout/tests/fixtures/codian_spec_43_46_1280x720.json`.

## Ошибки, найденные этим способом

Первая версия расчёта дала **три** неверных класса раскладок — все исправлены
до слияния:

1. **Инверсия ярусов** (№21, №23, №29, №31, №42): инвертировать надо
   геометрию, а не порядок списка.
2. **Индексы квадрантов** (№34–№37): порядок — 0=ЛВ, 1=ПВ, 2=ЛН, 3=ПН.
3. **Счёт окон в PIP-раскладках**: вендорный PIP считается отдельным окном.
