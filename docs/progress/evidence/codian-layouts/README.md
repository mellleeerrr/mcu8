## Как воспроизвести

1. **Извлечь чертежи** из спецификации (в репозиторий они не попадают — 55 PNG, 460 КБ):

   ```bash
   mkdir -p docs/progress/evidence/codian-layouts/drawings
   unzip -o -j "/home/pro/Документы/MCU/Codian_MCU4200_Video_Layouts_Specification.docx" \
     'word/media/*' -d docs/progress/evidence/codian-layouts/drawings
   # image1..image3 — обложка/служебные, image4..image55 — чертежи макетов #1..#52
   ```

2. **Проверить согласие таблицы и чертежей** (печатает `ТОПОЛОГИЯ СОВПАЛА В 52/52`):

   ```bash
   python3 docs/progress/evidence/codian-layouts/validate_topology.py
   ```

3. **Проверить покрытие канваса** (печатает `все 52 раскладок согласованы`):

   ```bash
   python3 docs/progress/evidence/codian-layouts/gen_codian.py
   ```

4. **Перегенерировать Rust-файл** (если правки вносились в таблицу):

   ```bash
   python3 docs/progress/evidence/codian-layouts/emit_codian_rs.py > crates/vks-layout/src/codian.rs
   ```

## Метод и его границы

* **Структура** (число окон, состав, явные дроби вида 2/3, 4/9, 5/6) берётся из
  **спецификации** — это истина.
* **Чертежи вендора** используются как **независимая проверка топологии**
  (число окон + карта крупных окон) и как источник пропорций, **когда спека
  молчит**. Это **оракул теста**, а не производственные данные: в
  `crates/vks-layout/src/codian.rs` попадают **рациональные** пропорции.
* **Чертёж схематичен.** Пример: для макета №5 спецификация говорит «4/9 экрана»,
  а чертёж показывает крупное окно высотой 2/5. Точных пикселей нет ни у одного
  источника — есть структура, и её берём из спецификации.
* **«Дрожащие» пропорции** макетов №43 (ряды 5/28, 5/28, 6/28, 6/28, 6/28) и
  №49 (15/36, 7/36, 7/36, 7/36) взяты как измеренные рационали: отклонение от
  чертежа ≤ 1,3 px, тогда как «красивые» дроби 1/6 и 2/9 дают 2,3 px.

## Проверка в CI

Продакшн-часть проверяется тестом
`crates/vks-layout/tests/codian_layouts.rs` (6 тестов): число окон каждого
макета, точное покрытие канваса без пересечений, границы PIP-окон, делимость
областей, длина массива ролей, поведение на неизвестном id.

## Ошибки, найденные этим способом

Первая версия расчёта дала **три** неверных класса раскладок — все исправлены
до слияния:

1. **Инверсия ярусов** (№21, №23, №29, №31, №42): инвертировать надо
   геометрию, а не порядок списка.
2. **Индексы квадрантов** (№34–№37): порядок — 0=ЛВ, 1=ПВ, 2=ЛН, 3=ПН.
3. **Счёт окон в PIP-раскладках**: вендорный PIP считается отдельным окном.
