# Live E2E (Playwright API)

`live.js` uses the `playwright` Node API directly (not the `@playwright/test`
runner), because the scenario is a live browser session against a running
stand, not a fixture-based test suite. There is no `playwright.config.ts` and
`npx playwright test` is not used.

## Install

```bash
cd tests/e2e
npm ci
npx playwright install chromium
```

`npm test` runs `node live.js`. The script auto-detects a local Chromium only
when `VKS_CHROMIUM` is unset; override it if your cache path differs.

## Run

```bash
VKS_BASE_URL=http://127.0.0.1:8080 \
VKS_LOGIN=admin VKS_PASSWORD=admin_password \
VKS_SIP_URI=sip:probe-e2e@192.168.1.132 \
npm test
```

Artifacts go to `VKS_ARTIFACTS` (default `artifacts/e2e`): `result.json`,
`network.json`, screenshots, `trace.zip`. The script creates and removes its
own test rooms; it requires the live server and the remote SIP terminal.
Set `VKS_PASSWORD` for non-dev configs.

## `label-zoom.js` — подпись в плитке раскладки + счётчики мониторинга

Живой измеритель (Playwright API) без внешнего SIP-терминала:

- (A) открывает страницу раскладок конференции, перебирает все размеры
  раскладки (1, 2, 3, 4, 5+, 8, 9, 10+, 25, 34+), заново сажает контакт в
  ячейку 1 (при смене размера посадка сбрасывается) и меряет подпись
  `.layout-grid-slot-dn__text` относительно плитки: font-size, bbox,
  `dx`/`dy` (центровка), попадание внутрь плитки, переполнение;
- (A2) проверяет, что аватар участника в плитке НЕ отображается: принимается
  любой механизм скрытия (`display:none`, `visibility:hidden`, `opacity:0`,
  нулевой bbox, обрезка/вынос из плитки, отсутствие в DOM) — и что подпись при
  этом ничем не отжимается вниз (0 em вместо 1.335 em). Плюс негативные
  контроли: аватары ВНЕ плитки (панель видеслота, таблица «Получатели», шапка)
  обязаны остаться видимыми, иконка роли в пустой плитке не должна сдвинуться,
  а плитка с превью кадра (MediaPreview 24×24, где аватара в DOM нет) — тоже
  центрирована;
- (A3) проверяет, что аватар убран **из потока**, а не просто «невидим»: его
  бокс должен иметь нулевую площадь (иначе `visibility:hidden`, `opacity:0` и
  скрытие только внутреннего `.tc-avatar` прошли бы как «скрыто», оставив дыру
  2em);
- (A4) проверяет, что страховка плитки с превью **живая**: сдвиг превью-плитки
  должен отличаться от сдвига обычной ровно на `12px + .335em` (половина
  превью 24px + половина gap .67em) — иначе правило умерло молча;
- (A5) проверяет, что подпись не переполняется по вертикали, а горизонтальная
  обрезка длинного имени идёт **только** через вендорский `ellipsis` и не
  выходит за плитку;
- (B) сверяет счётчики списка мониторинга («Участники (SIP/H.323)»,
  «Устройства (VNC/RTSP) и медиафайлы») с `/api/v3/ui/conferences`, с
  `/api/v3/conferences/{id}/contacts` и с шапкой карточки комнаты.

```bash
VKS_BASE_URL=http://127.0.0.1:8080 \
VKS_LOGIN=admin VKS_PASSWORD=admin_password \
NODE_PATH=tests/e2e/node_modules node tests/e2e/label-zoom.js
```

Два служебных режима (нужны, чтобы харнесс сам себя проверял):

```bash
# прогон с кандидатом фикса, инъектированным в страницу (index.html не трогаем):
VKS_APPLY_CANDIDATE=1 node tests/e2e/label-zoom.js     # ожидается exit 0
# самопроверка: откатываем фикс (аватар снова виден) — прогон ОБЯЗАН упасть:
VKS_REVERT_CHECK=1 node tests/e2e/label-zoom.js         # ожидается exit 1
```

`CANDIDATE_CSS` в `label-zoom.js` обязан совпадать с продом
(`client/pnm-frontend/deployed/pnm/index.html`, блок `#prostor-pnm-overrides`),
иначе режим `VKS_APPLY_CANDIDATE=1` проверяет не то, что реально раздаётся.

Переменные: `VKS_CONFERENCE_ID` (по умолчанию — комната с контактом
«T12b Label Probe»), `VKS_PARTICIPANT`, `VKS_ARTIFACTS` (по умолчанию
`artifacts/e2e-label-zoom`), `VKS_CHROMIUM`, `VKS_APPLY_CANDIDATE`,
`VKS_REVERT_CHECK`. Коды выхода: `0` — все проверки прошли, `1` — провалена
проверка, `2` — прогон упал (логин/страница/нет контакта в комнате).
Скрипт ничего не пишет в живую БД: «Создать» не нажимается, единственный
не-GET запрос — `POST /api/v3/ui/video_layouts/calculate`.

## `audio-in-layouts.js` — вкладка «Аудиоканал» переехала в «Раскладки»

Живой контракт переезда вкладки аудиоканалов (PNM 2.2.1.66). Проверяются ДВА
таб-бара: конференции (`/pnm/monitoring/conferences/{id}`) и сессии
(`/pnm/monitoring/sessions/{id}`, тот же UUID — у сессии свой таб-бар).

Конференция:

- (C1) в таб-баре конференции (`.tc-tabs.main-card__tabs`, `role="tablist"`)
  НЕТ отдельной вкладки аудиоканалов — ни по вендорскому `data-qa`
  `conference-audio-tab`, ни по тексту «Аудиоканал»;
- (C2) осталось ровно 7 вкладок в ожидаемом порядке: Информация, Основное,
  Расписание, Раскладки, Оформление, Запись и трансляция, Дополнительно
  (`conference-{info,general,schedule,layouts,skins,record-and-stream,additional}-tab`);
- (C3) у вкладок целы `role="tab"`, `tabindex` и `aria-selected` (ровно одна
  активная, совпадает с `mdc-tab--active`);
- (C4) каждая оставшаяся вкладка открывается и показывает ИМЕННО своё
  содержимое (корневой класс компонента: `.conference-info`,
  `.conference-general`, `.layouts`, `.conference-skins`,
  `.conference-record-and-stream`, `.conference-additional`; для «Расписания» —
  текст «Продолжительность конференции»);
- (C5) блок аудиоканалов `.conference-audio-channels` лежит ВНУТРИ панели
  вкладки «Раскладки» (тот же контейнер `.main-card-content`, что и `.layouts`),
  а не в отдельной панели;
- (C6) блок аудиоканалов не «спрятан», а переехал: он видим (учитываются
  `display`, `visibility`, `opacity`, нулевой bbox, `checkVisibility`), в
  документе ровно один и сохраняет функциональность (таблица каналов либо
  пустое состояние с кнопкой «Добавить»);
- (C7) блок аудиоканалов не смонтирован в остальных вкладках;
- (C8) редактор раскладок (маршрут `.../layouts`) продолжает работать: 10
  размеров (1, 2, 3, 4, 5+, 8, 9, 10+, 25, 34+), посадка контакта, подпись
  ровно ×2 к шрифту плитки, центрирована и целиком внутри плитки;
- (C9) `pageerror` = 0, console errors = 0, счётчики в шапке карточки не
  изменились, ни одного запроса на запись в БД.

Сессия (тот же контракт, настоящий маршрут):

- (S1) в таб-баре сессии ровно 6 вкладок в порядке `session-main-tabs-control-panel`,
  `session-main-tabs-general`, `session-main-tabs-layouts`,
  `session-main-tabs-skins`, `session-record-and-stream-tab`,
  `session-main-tabs-additional`; НЕТ `session-main-tabs-audio` и вкладки
  «Аудиоканалы»;
- (S2) блок `.session-audio-channels` — второй ребёнок панели «Раскладки»
  сессии: видим, единственный, функционален, в остальных вкладках не смонтирован.

Дополнительные проверки (D1–D9 регрессионного аудита):

- (D2a) **инвариант «активная вкладка == видимая панель»** на каждой вкладке
  обоих таб-баров: ровно одна `aria-selected="true"`, и отрисовано содержимое
  именно её (у вендорской панели в DOM НЕТ `data-qa`, поэтому идентичность
  панели определяется по корневому классу компонента вкладки; «чужой»
  маркер другой вкладки в панели отсутствует);
- (D2b/D7) круг «Добавить» в блоке аудиоканалов → переход в редактор
  (`.../audiochannels`) → «Отмена» (НЕ «Создать»): URL возвращается на
  страницу конференции/сессии, ровно одна вкладка с `aria-selected="true"`
  (это «Раскладки»), панель непустая, блок аудиоканалов ВНУТРИ панели этой
  вкладки. «Добавить» в вендоре только кладёт черновик в Vuex и меняет
  маршрут — записи в БД нет;
- (D5) футер вкладки не изменился: на «Раскладках»/«Информации» (конференция)
  и «Панели управления»/«Раскладках» (сессия) футера нет, на остальных — ровно
  «Отмена» + «Сохранить». ВНИМАНИЕ: в билде 2.2.1.66 `TcButton` не
  пробрасывает `data-qa` в DOM, поэтому атрибутов `main-card-cancel-button` /
  `main-card-save-button` в кнопках футера НЕТ (проверяется отдельной
  диагностикой с severity `known-issue`), а сам футер сверяется по подписям;
- (D8) на вкладке «Раскладки» в панели ровно ДВА `.main-card-body`
  (раскладки + аудиоканалы), аудио-блок — второй ребёнок того же
  `.main-card-body__container`;
- (D3) клавиатура по таб-бару настоящей правки — для ОБОИХ таб-баров
  (конференции и сессии): 3×`ArrowRight` от «Раскладок» → фокус
  `layouts → skins → record-and-stream → additional` (фокус не застревает, ещё
  одно нажатие уводит дальше), `Enter` активирует сфокусированную вкладку,
  панель следует за ней, `aria-selected` совпадает с `mdc-tab--active`;
  конференция: `conference-skins-tab → conference-record-and-stream-tab →
  conference-additional-tab`, сессия: `session-main-tabs-skins →
  session-record-and-stream-tab → session-main-tabs-additional`;
- (D9) «сиротских» панелей нет: в активной панели ровно один `.main-card-body`
  (на «Раскладках» — два), панель непустая;
- (D-guard) за весь прогон ни одного non-GET, кроме `POST /api/v3/login` и
  `POST /api/v3/ui/video_layouts/calculate` (расчёт черновика раскладки).

Высотная политика T15 и обрезка блока аудиоканалов (N7). Проверка «bbox > 0»
обрезку не ловит, поэтому меряются границы:

- (N7.1) нижняя граница кнопки «Добавить» ≤ нижняя граница
  `.main-card-body__container` + 1px;
- (N7.2) нижняя граница самого блока аудиоканалов ≤ нижняя граница контейнера
  + 1px (блок может резать контейнер, даже если кнопка ещё влезает);
- (N7.3) кнопка «Добавить» целиком видна ВНУТРИ блока аудиоканалов: у блока
  своя прокрутка и `max-height:320px`, он может срезать контент изнутри;
- (N7.4) у контейнера панели нет вертикального переполнения
  (`scrollHeight ≤ clientHeight + 1`);
- (N7.5) иллюстрация пустого состояния блока аудиоканалов занимает не больше
  120×120 (вендорские 240×240 недопустимы);
- (N7.5b) **политика T16**: иллюстрация пустого состояния аудиоканалов ВИДИМА
  (`display != none`, `visibility: visible`) и имеет computed-размер ровно
  120×120 (±1px); пропорции не искажены — бокс квадратный, `naturalWidth ==
  naturalHeight == 150` (в SVG 150×150, в бокс 120×120 — равномерное
  масштабирование);
- (N7.9) иллюстрация пустого состояния списка РАСКЛАДОК (`BSmrOOY7.svg`) —
  тоже видима и ровно 120×120. На конференции список пуст, картинка есть; на
  сессии список не пуст, картинки нет — тогда проверка неприменима и
  фиксируется как `info`, а не `FAIL`;
- (N7.10) НИ одна из этих иллюстраций не равна вендорским 240×240 — это
  значило бы, что наш override не применился (ровно этот откат обязан давать
  FAIL в режиме `VKS_CLIP_CHECK=1`);
- (N7.11) **правило 120×120 не расползлось за пределы панели «Раскладки»**:
  вне неё иллюстрации пустых состояний остаются вендорскими 240×240 —
  пустое состояние панели управления сессии (`CkOvTFTY.svg`) и пустое
  состояние контактов на странице списка сессий (`D50U8FhX.svg`, 240×240);
- (N7.6) блок аудиоканалов не выше своей `max-height` (320px);
- (N7.7) два блока ровно заполняют панель: `раскладки + аудио − контейнер = 0`
  (допуск ±2px) — нет ни пустого места, ни наложения;
- (N7.8) список раскладок: своей прокрутки нет (`scrollHeight == clientHeight`)
  на 1600×1000, 1280×800, 1024×768 и 820×1180; на 1280×600 карточка (381.8px)
  ниже вендорного контента (403px) и список скроллится сам — такая же
  прокрутка есть в вендорной базе, поэтому она допустима. На всех вьюпортах
  проверяется, что блок аудиоканалов при этом НЕ срезан (N7.1–N7.3).

одновременно скомпенсировала высоту вертикальным padding блока аудиоканалов

Служебные режимы. Правка в T15 структурная — это JS (переезд блока аудио в
панель раскладок), а не CSS; поэтому «откат» делается обратной правкой DOM
(блок аудиоканалов возвращается отдельной панелью, кнопка вкладки аудио
возвращается в таб-бар), а НЕ инъекцией стилей. Инъекция стилей используется
только в отдельном режиме проверки обрезки — там она нужна, чтобы вернуть
«старые» правила высоты.

```bash
# САМОПРОВЕРКА КОНТРАКТА (НЕ модель реализации!): имитируем «исправленное»
# состояние средствами DOM (вкладка аудио убрана из таб-бара, блок
# аудиоканалов перенесён в панель раскладок) и убеждаемся, что контрактные
# проверки достижимы. DOM-хирургия ломает клавиатурный фокус MDC, поэтому
# клавиатурная проверка здесь пропускается: этот режим НЕ может считаться
# доказательством поведения настоящей правки.
VKS_CHECKS_SELFTEST=1 node tests/e2e/audio-in-layouts.js   # ожидается exit 0
# самопроверка отката: собираем «исправленное» состояние, потом откатываем
# (вкладка аудио возвращается, блок уезжает из панели раскладок — и на
# конференции, и на сессии) — прогон ОБЯЗАН упасть:
VKS_REVERT_CHECK=1 node tests/e2e/audio-in-layouts.js      # ожидается exit 1
# самопроверка отката политики T16 (и обрезки N7): инъекцией стилей
# возвращаем «старые» правила и убеждаемся, что контрактные проверки это
# ловят — прогон ОБЯЗАН упасть. Варианты отката:
#   A) вендорские 240×240 у обеих иллюстраций (наш override не применился) —
#      падают N7.5, N7.5b, N7.9, N7.10;
#   B) политика T15: иллюстрация аудиоканалов скрыта (display:none) — падает
#      N7.5b (контракт видимости);
#   C) полное состояние до T15/T16 (оба блока по своей высоте, картинки
#      240×240, контейнер overflow:hidden) — блок аудио выходит за нижний
#      край контейнера, падают N7.1–N7.4;
#   D) нынешняя политика max-height:320px, но со старой видимой картинкой
#      240×240 — кнопка «Добавить» срезана ВНУТРИ блока (падает N7.3).
# Каждый вариант имеет собственную проверку воспроизведения («откат реально
# ломает контракт») — она обязана быть зелёной, иначе FAIL означал бы не то.
VKS_CLIP_CHECK=1 node tests/e2e/audio-in-layouts.js        # ожидается exit 1
```

Исторический алиас `VKS_SIMULATE_FIX=1` работает как `VKS_CHECKS_SELFTEST=1`,
но печатает предупреждение: это самопроверка контракта, а не модель
реализации и не доказательство поведения настоящей правки.

Переменные: `VKS_CONFERENCE_ID`, `VKS_SESSION_ID` (по умолчанию — тот же UUID),
`VKS_PARTICIPANT`, `VKS_ARTIFACTS` (по умолчанию
`artifacts/e2e-audio-in-layouts`), `VKS_CHROMIUM`, `VKS_CHECKS_SELFTEST`
(алиас `VKS_SIMULATE_FIX`), `VKS_REVERT_CHECK`, `VKS_CLIP_CHECK`. Коды выхода:
`0` — все проверки прошли, `1` — провалена проверка, `2` — прогон упал
(логин/страница).

Про недоступность сервера: если во время прогона стенд не отвечает (рестарт
сервера, обрыв WebSocket), сетевые ошибки отделяются от ошибок приложения —
консольные ошибки сети и `pageerror` в этом случае не блокируют прогон, но
фиксируются как `known-issue` с указанием числа неудачных запросов. Обычная
отмена запроса браузером (`net::ERR_ABORTED`, например превью видео при переходе
на другую страницу) ошибкой среды не считается.

Чего харнесс НЕ проверяет (и почему): реальное создание/удаление аудиоканала
требует записи в БД, поэтому кнопка «Создать» в редакторе аудиоканала не
нажимается (нажимается только «Отмена»); содержимое списка аудиоканалов при
непустой БД проверяется по наличию таблицы, а не по содержимому; маршрут
`/pnm/monitoring/sessions` (список) в таб-бар не превращается и в контракт не
входит — контракт сессии проверяется на её настоящем маршруте
`/pnm/monitoring/sessions/{id}`; панель вендера не отдаёт `data-qa`, поэтому
инвариант «активная вкладка == видимая панель» проверяется по корневому классу
компонента, а не по атрибуту.
