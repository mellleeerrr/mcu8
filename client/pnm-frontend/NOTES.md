## Как обновлять

```bash
VKS_PNM_ARCHIVE=/path/to/new.zip ./scripts/import-pnm-frontend.sh --force [--with-source]
```

Скрипт делает четыре слоя работы (раньше делал только первый — остальные терялись):

1. **Вендорный рантайм 1:1** — распаковка архива, копирование `deployed/pnm`,
   вычистка симлинков и `*.bak*`.
2. **Проектный слой** — сохраняются и восстанавливаются `perf-overrides.js`,
   `api-errors.js`, `codian-layouts.js`, `theme-toggle.js`, `deeplink.js`,
   блок `<!-- prostor:project-layer -->` и блок
   `<style id="prostor-pnm-overrides">` из `index.html` (в вендорском архиве их
   нет, а копирование 1:1 их бы уничтожило). Правки T1.1/T07/T12b/T13/T14/T15,
   живущие в этих файлах, переживают переимпорт.
3. **Вендорские патчи** — `scripts/patch-pnm-chartjs.py` (T11b) и
   `scripts/patch-pnm-audio-in-layouts.py` (T15) применяются к свежему рантайму
   **до** пересборки манифеста, поэтому манифест считается по итоговым байтам.
   Патч-скрипт обязан упасть с ненулевым кодом, если вендор изменился
   (число вхождений якорей не совпало) — импорт тогда прерывается.
4. **Манифест** — `MANIFEST.sha256` пересобирается по итоговому дереву.

**Что импорт НЕ применяет:** слой PROSTOR-ребренда (`frontend/06-rebrand/`,
вне репозитория). После импорта скрипт печатает об этом напоминание —
проверьте `index.html` (`<title>PROSTOR</title>`) и локали `ru_RU`/`en_US`
и примените ребренд вручную.

Проверка целостности после импорта:

```bash
cd client/pnm-frontend/deployed/pnm && sha256sum -c ../../MANIFEST.sha256
```

## Правки рантайма и кэш (важно)

- Чанки **не содержат content-hash** (`index.bundle-2.2.1.66.js` — это версия сборки, не хэш),
  исторически правились in-place. Поэтому сервер отдаёт `chunks/**` с `Cache-Control: no-cache`
  (клиент ревалидирует; `Last-Modified`/304 — от `ServeDir`), а `immutable` — только реально
  хэшированные `assets/fonts/**`, `assets/images/**`, `assets/*.webm`.
- Любая ручная правка файла обязана сопровождаться cache-bust: обновить ссылку в `index.html`
  (`…?v=<версия-правки>`) или имя файла. Иначе у клиента до года будет старый JS.
  **Исключение — `chunks/**` и `index.html`:** они отдаются с `Cache-Control: no-cache`
  (клиент ревалидирует по `Last-Modified`), поэтому для них cache-bust не нужен —
  это подтверждено и живой проверкой заголовков, и правками T11b/T15. Cache-bust
  обязателен для `assets/**` (там `immutable`).
- `--gzip` больше не нужен (T07): сжатие статики делает tower-http `CompressionLayer`
  в рантайме; флаг принимается, но игнорируется с предупреждением. `.gz`-файлы не
  должны появляться в рантайме и в манифесте (их отсутствие проверяет
  `scripts/check-pnm-runtime.py`). Ответы статики несут `Vary: Accept-Encoding`.
- CSP вычисляется сервером **при старте** из `index.html` (sha256 всех inline-скриптов) — правки
  inline-скриптов политику не ломают; если в `index.html` появятся внешние домены
  (`https://cdn…`), их нужно добавить в `frontend.rs::build_csp`.

## Политика симлинков

Рантайм `deployed/pnm/` **не содержит симлинков** — это инвариант, его проверяет тест
`runtime_tree_has_no_symlinks` (`crates/vks-server/src/frontend.rs`). Причина: `tower-http::ServeDir`
следует по симлинкам, поэтому ссылка внутри дерева = потенциальный escape за пределы корня статики.
`scripts/import-pnm-frontend.sh` при импорте удаляет все симлинки из скопированного дерева
(каждый удалённый — в логе импорта). Если в новой версии архива появятся симлинки — их появление
будет видно в логе импорта; дерево всё равно останется без симлинков.

## T11b: Chart.js v4 в `index3.bundle` (2026-10-22)

В бандле 2.2.1.66 графики статистики собраны под Chart.js v2 (`yAxes`/`xAxes`,
`gridLines`, `fontSize`, `legend.labels.fontColor`), а в комплекте Chart.js v4:
консоль давала `Invalid scale configuration for scale: yAxes/xAxes/responsive`,
оси и легенда не рисовались. Правка in-place в
`deployed/pnm/chunks/index3.bundle-2.2.1.66.js`:
`yAxes/xAxes` → `y/x`, `gridLines` → `grid`, `fontSize` → `font.size`,
`legend.labels.fontColor` → `plugins.legend.labels.color`; ошибочно вложенные
`responsive`/`maintainAspectRatio` вынесены из `scales` в корень options,
`min/max` перенесены с `ticks` на уровень `scales.y`. В `index9.bundle`
оба варианта `shouldUpdateLabels` и `shouldUpdateData` TcLineChart защищены
от вызова до создания chart (line-режим памяти больше не даёт TypeError).
Правка воспроизводится байт-в-байт скриптом `scripts/patch-pnm-chartjs.py`;
хэши `index3`/`index9` в `MANIFEST.sha256` обновлены (остальные файлы манифеста уже были изменены
предыдущими правками и не являются pristine-эталоном).
Проверено live: `/pnm/administration/statistics` — 0 console/page errors и в
pie-, и в line-режиме памяти, 6/6 виджетов, оси CPU/resources/workers 0..100%,
память line 0..58 Gb. Файл ревалидируется (`Cache-Control: no-cache`),
поэтому cache-bust не требуется.

## T15: вкладка «Аудиоканал(ы)» → внутрь вкладки «Раскладки» (2026-10-22)

Заказчик: «перемести вкладку аудиоканалы во вкладку раскладки». Перестановка
верхнего ряда бессмысленна — «Аудиоканал» и так стоит сразу после «Раскладок»
и на странице конференции, и на странице сессии. Реализовано слияние: вкладка
исчезает из верхнего ряда, а её содержимое живёт **внутри панели «Раскладки»**.

| | конференция | сессия |
|---|---|---|
| вкладок было/стало | 8 → 7 | 7 → 6 |
| вкладка | `conference-audio-tab` («Аудиоканал») | `session-main-tabs-audio` («Аудиоканалы») |
| панель аудио | `.conference-audio-channels` | `.session-audio-channels` |

**Это не CSS-задача.** Панель вкладок одна, монтируется только активная
(`currentComponent` в `index6.bundle`), а Vue при размонтировании компонента
удаляет его корневой узел из DOM (`remove: e => e.parentNode.removeChild(e)`) —
поэтому «перенести блок» средствами CSS/DOM нельзя, нужен патч вендорного чанка.
Скрытие кнопки вкладки через CSS отвергнуто замерами: MDC держит список
`.mdc-tab` по селектору (8 элементов при 7 видимых) ⇒ клавиатурная ловушка
(фокус не двигается по `display:none`-кнопке) и «нет активной вкладки».

### Патч `scripts/patch-pnm-audio-in-layouts.py`

14 правил на каждый чанк (`index6.bundle` и `index-legacy6.bundle`), идемпотентно.
Проверка «уже применено» — **по правилу**: якорь «до» отсутствует (0 вхождений)
И якорь «после» присутствует в ожидаемом количестве. Раньше для этого
использовался один глобальный маркер; он доказывал применение только первого
правила и маскировал частично пропатченный/подменённый вендор («уже применено»
для всех 10 правил при exit 0) — теперь такой случай даёт exit 1.
Дополнительно: запись атомарная (временный файл + `os.replace`), после записи —
`node --check` (при ошибке синтаксиса файл откатывается), и проверка наличия
CSS-override геометрии в `index.html` (без неё панель делится 50/50).
Смена вендора ⇒ ненулевой код возврата ⇒ импорт прерывается.

1. `tabList`: пункт «Аудиоканал(ы)» получает `hidden:!0`. `TcTabs` фильтрует
   `tabs.filter(e => !e.hidden)` ⇒ кнопка не рендерится вообще, MDC её не видит,
   индексы/aria/клавиатура не разъезжаются.
2. Таб-бару передаётся `modelValue:e.conferenceCurrentTab==="Audio"?"Layouts":e.conferenceCurrentTab`
   (и то же для сессии) — «залипшее» состояние `Audio` всё равно подсвечивает
   «Раскладки», т.е. **активная вкладка всегда совпадает с видимой панелью**.
3. В рендер компонента `LayoutTab` вторым ребёнком `main-card-body__container`
   вставляется панель аудиоканалов (`(s(),b(wp,{key:3}))` / `(s(),b(PS,{key:3}))`;
   в legacy — `(U(),Y(Jr,{key:3}))` / `(U(),Y(sv,{key:3}))`). Явный `key` — страховка
   на будущее: измерением перемонтирования панели раскладок при авто-refresh
   (35 с, 7 циклов) показано **0 перемонтирований и с ключом, и без него**
   (список детей всегда один и тот же, в одном порядке) ⇒ «обязательным» key
   называть нельзя, но он безвреден и оставлен.
4. `currentComponent`: `Audio:wp` → `Audio:iy` (конференция), `Audio:PS` → `Audio:PT`
   (сессия) — страховка от «пустой карточки» без единой ошибки в консоли.
5. Шесть присваиваний `this.conferenceCurrentTab="Audio"` / `this.sessionCurrentTab="Audio"`
   (возврат из отдельной страницы редактора аудиоканала: «Назад», «Отмена»,
   «Создать») перенаправлены на `"Layouts"` — по одному site-уникальному
   якорю на каждое место (6 правил: `goBackHandler`, `cancelHandler`,
   `finally` × конференция/сессия). Общий якорь `CurrentTab="Audio"` был
   непригоден для проверки «после»: в вендоре строка `"Layouts"` встречается
   уже один раз (возврат из редактора раскладок), и после патча — четыре,
   поэтому «после» нельзя отличить от вендорского.

### Вёрстка объединённой панели

Вендор задаёт `.main-card-body { flex: 1 1 1px }`, поэтому два блока в панели
делили высоту 50/50, и пустой блок аудиоканалов занимал пол-экрана. Вариант
«оба блока по контенту + прокручиваемый контейнер» тоже не годится: суммарный
контент пустого состояния (807 px) больше карточки (783.7 px) ⇒ flexbox
сминает заголовок карточки (74.2 → 56 px) и блок аудиоканалов уезжает за нижнюю
границу карточки (`overflow: hidden`) — кнопка «Добавить» становится
недостижимой. Это видно только на низких вьюпортах (1280×800, 1024×768,
1280×600); на 1600×1000 карточка выше и дефект не проявляется.

Итоговая политика (в `<style id="prostor-pnm-overrides">`, index.html):

- **блок аудиоканалов** — `flex: 0 0 auto; min-height: 0; max-height: 320px;
  overflow-y: auto`: своей высоты, но не выше 320 px ⇒ не выпирает из карточки
  и не сжимает заголовок; при большом числе каналов скроллится сам;
- **список раскладок** — возврат к вендорскому `flex: 1 1 1px` (правило
  `:has(...) > .main-card-body:first-child`, специфичность 0,5,0 перебивает
  прежнее 0,4,0): растёт на всю оставшуюся высоту и сжимается, когда места
  мало (свой скролл) — вендорский паттерн остальных вкладок;
- **иллюстрации пустых состояний — 120×120** (T16, см. §T16): и у списка
  раскладок, и у блока аудиоканалов, плюс компактные отступы
  `.main-blank__content > :not(:last-child){margin-bottom:12px}`;
- **тело таблицы аудиоканалов** `min-height: 140px`: вендорский
  `.tc-list { flex: 1 1 80px }` показывал всего 2 строки из 12+;
- контейнер панели `overflow-y: auto` — страховка.

Замеры на живом стенде (5 разрешений × 3 сценария = 15 комбинаций, политика
T16): заголовок карточки 74.2 px во всех, оба блока внутри карточки во всех,
кнопка «Добавить» видна во всех, горизонтального переполнения нет,
переполнения контейнера 0. Пустое состояние: 1600×1000 — раскладки 519.6,
аудио 262.2; 1280×800 — 319.6 / 262.2; 1024×768 — 287.6 / 262.2;
820×1180 — 699.6 / 262.2; 1280×600 — 119.6 / 262.2 (здесь список раскладок
скроллится сам — как и в вендорной базе, где контейнер 381.8 < контента).
При 12 и 39 каналах блок аудио = 275 px, тело таблицы = 140 px, панель не
прокручивается.

Специфичность правил 0,3,0 / 0,4,0 / 0,5,0 выше вендорской 0,1,0 — это
обязательно: CSS чанка 7 (`.conference-audio-channels`, `.layouts`) Vite
подключает **рантаймом**, то есть ПОСЛЕ инлайн-блока `#prostor-pnm-overrides`,
и правило равной специфичности проиграло бы по порядку в документе.
Правила с `:has()` работают в современных браузерах; базовые (`flex`,
`max-height`, `min-height`) — везде, включая legacy-сборку.

## T16: иллюстрации пустых состояний вдвое меньше (2026-10-23)

Заказчик: «сделай меньше в 2 раза» — про две картинки пустого состояния в
объединённой панели «Раскладки»:

| файл | компонент вендора | где |
|---|---|---|
| `assets/images/BSmrOOY7.svg` | `LayoutBlank` | пустое состояние списка раскладок |
| `assets/images/eNWXoy3B.svg` | `AudioChannelBlank` | пустое состояние списка аудиоканалов |

Вендорское правило — `.main-blank__image { height: 240px; width: 240px }`
(специфичность 0,1,0) в `chunks/index.bundle-2.2.1.66.css`; обе SVG
квадратные (`viewBox="0 0 240 240"`, `naturalWidth/Height` = 150×150) ⇒ 120×120
это ровно половина без искажения пропорций.

Политика (в `<style id="prostor-pnm-overrides">`, index.html):

- **обе иллюстрации — 120×120 и видимы**. Для иллюстрации аудиоканалов это
  означает отмену правила T15 `display: none` (в T15 картинка была скрыта,
  чтобы пустое состояние раскладок помещалось в карточку);
- **компенсация высоты**: вертикальный padding блока аудиоканалов 16 px → 12 px
  (вендор: `.conference-audio-channels { padding: 16px 0 }` из
  `chunks/index7.bundle-2.2.1.66.css`, который подключается рантаймом ПОСЛЕ
  инлайн-блока ⇒ специфичность 0,3,0). Без неё сумма двух пустых состояний
  (283.2 + 269.2 = 552.4 px) превышала бы контейнер 549.8 px (1024×768), и
  список раскладок получил бы собственную прокрутку, а его кнопка «Добавить»
  уехала бы за нижний край блока. С padding 12 px сумма = 545.4 px, запас
  4.4 px;
- селекторы — **классовые, без `:has()`**, чтобы modern и legacy-сборка давали
  одинаковую геометрию (в legacy `:has()` отбрасывается целиком):

```css
.main-card-body__container > .main-card-body.conference-audio-channels .main-blank__image,
.main-card-body__container > .main-card-body.session-audio-channels .main-blank__image,
.main-card-body__container > .main-card-body.layouts .main-blank__image {
  width: 120px;
  height: 120px;
}
```

Область действия — ровно вкладка «Раскладки» конференции и сессии: класс
`.main-card-body.layouts` в вендоре встречается только там (2 вхождения в
`index6` и 2 в `index-legacy6`), редактор раскладок содержит другой DOM, а
остальные пустые состояния (контакты, панель управления сессии, медиафайлы)
лежат в других ветках и остаются 240×240 (проверено обходом 24 страниц).

Замеры (5 разрешений × 2 страницы × modern|legacy, стенд 127.0.0.1:8080):
обе картинки 120×120 и видимы везде; контейнер 781.8 / 581.8 / 549.8 / 961.8 /
381.8; блок раскладок 519.6 / 319.6 / 287.6 / 699.6 / 119.6; блок аудио 262.2
(конференция) и 227.6 (сессия); переполнение контейнера 0; заголовок карточки

вендорной базе скролл (контейнер 381.8 px меньше контента).

Ограничения: запас по высоте на 1024×768 — 4.4 px, он зависит от метрик
